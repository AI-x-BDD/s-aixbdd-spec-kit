# Rule 1 - 資料表必須歸屬負責介面並涵蓋 Key Entities

- 每張資料表的 `Note` 必須以「<介面編號>：」開頭，介面編號必須是「負責介面」之一。
- `Note` 在介面編號之後必須寫出需求依據：目標 spec 中存在的需求編號（US、FR、NFR、SC），或 Key Entities 項目名稱。
- 每個負責介面必須至少對應一張資料表。
- 不得為負責介面以外的介面設計資料表，也不得建立不屬於任何負責介面的資料表。
- 負責介面的需求依據引用的每個 Key Entities 項目，必須有對應的資料表；不單獨建表的項目，必須在併入的資料表 `Note` 說明併入該表。

## Good Example

- 圖書館借閱的負責介面為 D1 館藏資料存取與 D2 借閱紀錄持久化，需求依據引用 Key Entities 書目、館藏複本、讀者、借閱紀錄。每張表的 `Note` 以介面編號開頭並寫出需求依據；「讀者」由會員系統管理，只在 `loans` 保留讀者編號，並在 `Note` 說明併入。

```dbml
Table titles {
  id uuid [pk]
  isbn varchar(13) [not null, unique]
  Note: 'D1：Key Entities 書目；FR-001 依 ISBN 查詢館藏'
}

Table copies {
  id uuid [pk]
  title_id uuid [not null]
  barcode varchar(20) [not null, unique]
  Note: 'D1：Key Entities 館藏複本；FR-002 以條碼辨識每一本實體書'
}

Table loans {
  id uuid [pk]
  copy_id uuid [not null]
  reader_no varchar(12) [not null, note: '讀者由會員系統管理，只保存讀者編號']
  Note: 'D2：Key Entities 借閱紀錄，讀者併入此表的 reader_no；FR-004 借書、FR-005 還書'
}
```

## Bad Example

- 同一份需求中，`Note` 只寫表名，看不出屬於哪個介面與需求；Key Entities「館藏複本」沒有對應資料表，也沒有說明併入哪張表；另外多了一張不屬於任何負責介面的 `staff_accounts`。

```dbml
Table titles {
  id uuid [pk]
  isbn varchar(13) [not null, unique]
  Note: '書目表'
}

Table loans {
  id uuid [pk]
  title_id uuid [not null]
  reader_no varchar(12) [not null]
  Note: '借閱表'
}

Table staff_accounts {
  id uuid [pk]
  Note: '館員帳號'
}
```

# Rule 2 - 關聯與欄位約束必須反映需求

- 資料表之間的關聯必須以 `Ref` 表達，並以 `>`、`<` 或 `-` 標明基數；不得只在 `Note` 或欄位名稱暗示關聯。
- 每張資料表必須有主鍵。
- 需求中有固定狀態集合的欄位，必須以 `Enum` 定義，不得使用自由字串。
- 需求要求唯一的欄位或欄位組合，必須標 `unique` 或建立 `unique` 索引；需求要求必填的欄位，必須標 `not null`。
- 需求中的查詢條件或效能要求（例如 SC 的回應時間）所依賴的欄位，必須建立 `indexes`。

## Good Example

- 圖書館借閱需求寫明「同一本館藏複本同時只能有一筆未歸還的借閱」（FR-006）、借閱狀態分為借出中、已歸還、逾期（FR-007），以及「讀者查詢自己的借閱紀錄 1 秒內回應」（SC-002）。狀態用 `Enum`，關聯用 `Ref` 標明基數，查詢欄位建立索引；DBML 無法表達部分唯一索引，FR-006 改以 `active_copy_id` 欄位加 `unique` 表達，並在 `note` 說明。

```dbml
Enum loan_status {
  on_loan
  returned
  overdue
}

Table loans {
  id uuid [pk]
  copy_id uuid [not null]
  active_copy_id uuid [unique, note: '借出中時等於 copy_id，歸還後設為 null（FR-006）']
  reader_no varchar(12) [not null]
  status loan_status [not null, default: 'on_loan']
  borrowed_at timestamptz [not null]

  indexes {
    (reader_no, borrowed_at) [name: 'idx_loans_reader_borrowed']
  }

  Note: 'D2：Key Entities 借閱紀錄；FR-004、FR-006、FR-007；SC-002'
}

Ref: loans.copy_id > copies.id
```

## Bad Example

- 同一份需求中，狀態用自由字串，FR-006 的「同時只能有一筆未歸還借閱」沒有任何唯一約束，與 `copies` 的關聯只寫在 `Note`，SC-002 依賴的讀者查詢也沒有索引。

```dbml
Table loans {
  id uuid [pk]
  copy_id uuid
  reader_no varchar(12)
  status varchar(20) [note: '借出中、已歸還或逾期']
  borrowed_at timestamptz

  Note: 'D2：借閱紀錄，copy_id 對應 copies.id'
}
```
