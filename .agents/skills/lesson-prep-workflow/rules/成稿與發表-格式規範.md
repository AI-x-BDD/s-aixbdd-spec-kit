# Rule 1 - 全文與模擬試讀必須對應採用成果

- 大綱、初稿、試讀及定稿必須保存為可區分的成果；不得以大綱或篇幅增加代替完整文章。
- 全文必須依已載入的教學及證據檢查內容展開採用大綱，保留讀者完成成果所需的解說與提示詞；新增內容與重述必須引用備課Rule 6、8的必要性及品質檢查結果。
- 正式大標題必須指出文章回答的問題。
- 開頭可以使用課內情境／例子、直接提出本文問題，或有來源且適用的讀者研究案例；選用必須依已載入備課Rule 6，保存本文能回答的部分、用途與來源。只呈現產品除錯問題且本文未處理其關鍵前提時，該案例必須保留於研究資料。
- 小標必須準確表達本段內容；研究原詞適用且無額外產品歧義時，應採用並保留來源；其餘必須使用課程或正文已定義的詞，記錄不採原詞的理由。
- 作者未提供的個人經驗必須使用[我的經驗待填：具體內容]，不得代寫經驗。
- 結尾必須提供符合成果的全貌筆記及今天第一步；不得使用吊胃口或強迫導流話術。
- 模擬試讀必須逐段定位難詞、前提、跳步、卡點、新增內容及重述位置，依備課Rule 6、8提出可套用修改及最需優先處理項；真實讀者效果必須依證據清單另列。

## Good Example

- 自製書目情境依文章可回答的問題選開頭，研究資料仍保留。

1. 研究只有某產品按鈕失效問題，文章只教同名辨識；選用課內同名不同作者例，記錄產品案例留研究資料。
2. 小標採正文已定義的「比對作者」，記錄產品按鈕原詞會引入除錯歧義。
3. 若研究原話正問「同名卻不同作者怎麼辦」，可以作開頭並保留來源。
4. 試讀指出第2段缺作者處理及表後重述，分列補前提與刪減修改；保留作者經驗待填。

## Bad Example

- 相同書目文章只憑網址採用產品故障開頭，正文缺少對應內容。

1. 開頭呈現按鈕失效，卻只解釋作者不同時暫不合併。
2. 用產品錯誤訊息作小標，未說明與同名辨識的關係。
3. 以篇幅與題答完整宣稱教學通過，保留表後逐字重述。

# Rule 2 - 社群必須有獨立可用收穫

- 社群稿本身必須提供可用的觀念、判斷或步驟，並說明全文增加的內容與已提供網址；缺網址必須明列待補，不得造網址。
- 每個平台草稿必須符合本次平台限制，提供三種開頭供選擇，內容不得依賴未提供的作者經驗。
- 不得以「答案在留言」等吊胃口或強迫導流方式代替收穫。

## Good Example

- 自製情境保留可核對依據與限制。

- 三開頭分別用同名書問題、對照例、判斷準則；貼文本身說明先比作者，全文另附案例表，網址待補。

## Bad Example

- 相同情境遺漏依據或超出可支持的結論。

- 只寫「這招讓我省十小時，留言才給答案」，經驗與量測未提供。

# Rule 3 - 回顧必須依實際資料提出下一次驗證

- 回顧必須使用實際日期、收到的成效資料與讀者原話，區分觀察與推論；缺項必須列待補。
- 缺歷史基準時不得推定成長、衰退或因果趨勢。
- 下一次驗證必須只提出一個變數，附判斷方式及資料限制。

## Good Example

- 自製情境保留可核對依據與限制。

- 本週書目貼文曝光100（作者提供），無上週資料；下次只比較開頭問題句，觀察相同期間的回覆。

## Bad Example

- 相同情境遺漏依據或超出可支持的結論。

- 只有本週曝光100便宣稱成長一倍，建議同時換題、平台與發文時間。
