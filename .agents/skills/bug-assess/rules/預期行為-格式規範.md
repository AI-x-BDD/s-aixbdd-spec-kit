# Rule 1 - 畫面類問題固定列 4 項

- 使用者操作後畫面發生變化的問題（例如點擊、重新整理、送出、切換）必須判斷為畫面類問題。
- 畫面類問題的完整預期行為必須固定列「有反應、不位移、不閃爍、看得出完成」4 項。
- 靜態版面問題（例如文字被擠成兩行）不得套用固定 4 項，必須依 Rule 2 依問題列。

## Good Example

### Example 1

- 重新整理是使用者操作後畫面發生變化的問題，所以固定列 4 項。

情境：

- 回報：按「重新整理」時畫面抖動。

| #  | 預期行為                                                   |
| -- | ---------------------------------------------------------- |
| E1 | 有反應：按下「重新整理」後，立即看得出系統正在處理         |
| E2 | 不位移：載入前、載入中、載入後，清單與按鈕的位置和尺寸不變 |
| E3 | 不閃爍：已經顯示的內容在載入期間不消失再出現               |
| E4 | 看得出完成：載入結束後，看得出已經更新完畢                 |

### Example 2

- 按鈕文字被擠成兩行是靜態版面問題，不套用固定 4 項，只列和問題有關的行為。

情境：

- 回報：申請紀錄頁的「重送」按鈕文字被擠成直的兩行。
- 預期行為：E1 在 360px 與 1120px 寬度下，「重送」按鈕文字在同一行顯示。

## Bad Example

### Example 1

- 回報是畫面類問題，但只列「不抖動」一項，缺少有反應、不閃爍與看得出完成。

情境：

- 回報：按「重新整理」時畫面抖動。

| #  | 預期行為 |
| -- | -------- |
| E1 | 不抖動   |

### Example 2

- 靜態版面問題被套用固定 4 項；「有反應」與「看得出完成」和這個問題無關。

情境：

- 回報：申請紀錄頁的「重送」按鈕文字被擠成直的兩行。
- 預期行為：E1 有反應；E2 不位移；E3 不閃爍；E4 看得出完成。

# Rule 2 - 其他問題依問題列預期行為

- 非畫面類問題與靜態版面問題的完整預期行為必須依問題列。
- 每項預期行為必須是一個可以觀察的行為。
- 預期行為不得只寫「程式正確」「功能正常」等無法觀察的敘述。

## Good Example

- 預期行為指出可以觀察的結果與條件。

情境：

- 回報：e2e 測試依賴實際時間，換日後會失敗。
- 預期行為：E1 固定時間下結果相同。

## Bad Example

- 預期行為沒有指出可以觀察的結果，無法判斷測試是否符合。

情境：

- 回報：e2e 測試依賴實際時間，換日後會失敗。
- 預期行為：E1 程式正確。

# Rule 3 - 量測方式與通過標準必須具體

- 量測方式必須寫出操作、觀察對象與工具，使別人可以照著重做。
- 畫面類問題的量測方式必須寫出視窗寬度。
- 視窗寬度必須依 `ui/plan.md` 的版面斷點選擇，每個斷點兩側各選一個寬度。
- 不在範圍內的寬度必須寫明。
- 通過標準必須有數值或明確的是否條件。
- 「目前」欄必須依程式碼判斷。
- 症狀取決於時刻或日期時，量測方式必須寫出要模擬的時刻與模擬時刻的方法（例如在報告目錄放一個時鐘平移模組，用 `NODE_OPTIONS=--import` 預載到 Node 行程），不得要求等待實際時間。

## Good Example

### Example 1

- 量測方式寫出操作、觀察對象、工具與依斷點選出的寬度，並寫明不在範圍的寬度；通過標準是可以判斷的數值。

情境：

- 預期行為：E2 不位移。
- 版面斷點：`ui/plan.md` 規定 720px 以下改為卡片版面。
- 量測方式：以 Playwright 在 1120px 與 360px 兩種寬度各做一次，按下「重新整理」，記錄表格頂端的 `boundingBox()`；其他寬度（例如 900px）不在本次範圍。
- 通過標準：載入前、載入中、載入後，表格頂端座標的差值為 0。

### Example 2

- 症狀取決於時刻，量測方式寫出要模擬的時刻與方法，不等待實際時間。

情境：

- 回報：每天 00:00 的逾期掃描有時重複寄通知。
- 量測方式：用時鐘平移模組把排程行程平移到台北 23:59:30 與 00:00:30，各執行一次逾期掃描，記錄寄出的通知筆數。
- 通過標準：每筆逾期借用各寄 1 次。

## Bad Example

### Example 1

- 量測方式沒有操作、觀察對象與工具，通過標準是主觀的判斷。

情境：

- 預期行為：E2 不位移。
- 量測方式：看畫面。
- 通過標準：看起來不抖。

### Example 2

- 量測方式沒有寫視窗寬度；或寫了寬度，但和 `ui/plan.md` 的版面斷點無關。

情境：

- 版面斷點：`ui/plan.md` 規定 720px 以下改為卡片版面。
- 量測方式 A：用 Playwright 按下「重新整理」，記錄表格頂端座標。（沒有寬度）
- 量測方式 B：用 Playwright 在 1000px 與 1100px 寬度按下「重新整理」，記錄表格頂端座標。（兩個寬度都在同一側，和斷點無關）

### Example 3

- 量測方式要求等待實際時間，沒有寫出模擬時刻的方法。

情境：

- 回報：每天 00:00 的逾期掃描有時重複寄通知。
- 量測方式：等到台北 00:00 前後各執行一次。
