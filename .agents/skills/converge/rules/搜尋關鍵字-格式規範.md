# Rule 1 - 關鍵字只取本次新增介面

- 本次新增介面是 `plan.md` 系統介面盤點中，名稱與需求依據沒有寫明是前幾版既有、保留或沿用功能的介面；寫明的是既有介面。
- 關鍵字只能來自新增介面：API 合約中 tag 為該介面的 operationId、資料模型中所屬介面（TableGroup 或 Note）為該介面的資料表名稱，以及 `tasks.md` 中標出該介面編號的任務內以反引號標出的字串。
- 不得取既有介面的 operationId 與資料表名稱。
- 每個關鍵字必須記下所屬的新增介面編號。

## Good Example

- 關鍵字只來自新增介面 B5、D3、S1，每個都記下所屬介面；沿用的 B1 沒有被取用。

情境：

- 預約系統新增候補功能，`plan.md` 有 B5「候補登記 API」（新增）與 B1「既有預約 API（沿用）」。
- 關鍵字：`joinWaitlist`（B5）、`waitlist_entries`（D3）、`WAITLIST_CONFIRM_MINUTES`（S1）。
- 不取：`createBooking`、`bookings`。

## Bad Example

- 同一情境取合約全部 operationId 與全部資料表，沒有區分新增與沿用；`createBooking`、`bookings` 命中整個預約功能的檔案。

情境：

- 關鍵字：`joinWaitlist`、`createBooking`、`cancelBooking`、`waitlist_entries`、`bookings`、`users`。

# Rule 2 - 關鍵字必須是本次專屬的程式識別字

- 關鍵字必須是會出現在程式中的識別字：模組、函式、變數、資料表、欄位、Enum、環境變數或 operationId。
- 不得取檔案路徑、數字、HTTP 狀態碼、JSON 片段、畫面文字、命令與測試資料。
- 既有介面的任務或文件也使用的識別字（例如 `created_at`、`status`、`ErrorCode`）是通用識別字，不得取。

## Good Example

- 從 B5 的任務只取本次專屬的程式識別字，排除狀態碼、畫面文字、通用欄位與路徑。

情境：

- 關鍵字：`waitlistService`（B5）、`waitlist_position`（D3）。
- 不取：`409`、`"已加入候補"`、`created_at`、`src/services/waitlistService.ts`。

## Bad Example

- 同一情境取了狀態碼、通用欄位與測試資料，執行者只好自訂「長度至少 6」的篩選，不同執行者的搜尋範圍因此不同。

情境：

- 關鍵字：`409`、`created_at`、`Test@1234`。
- 執行者另外以「長度至少 6」篩選關鍵字。
