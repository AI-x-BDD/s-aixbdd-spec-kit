# SOP

## Phase 1 -- 讀素材並規劃

1. `READ` 使用者指定的逐字稿或既有 `notes.md` 與輸出位置，建立「素材輸入」。
2. `THINK` 判斷「素材輸入」是否缺少逐字稿或輸出位置；沒有缺漏時進入步驟 5。
3. `WRITE` 向使用者索取步驟 2 列出的缺少項目。
4. `CHECK` 使用者回覆：補齊時返回步驟 1；未回覆時停止執行。
5. `THINK` 「素材輸入」為多份 `notes.md` 時進入章級模式，判斷能否寫出小節之間的關係、使用順序或整體判斷；章級模式沒有可寫的內容時進入步驟 6，其餘情況進入步驟 7。
6. `WRITE` 回報「章級文章沒有新增價值」並結束。
7. `DELEGATE` 執行 `scripts/check_polisher.py` 取得「潤稿預檢結果」。先以此 `SKILL.md` 所在目錄解析腳本和 `polisher.json` 的絕對路徑，再執行 `uv run --script "<腳本絕對路徑>" --config "<設定絕對路徑>"`。
8. `CHECK` 潤稿預檢結果同時有退出碼 0 和含名稱、版本、commit、入口的 JSON 時，保存為本次唯一的「潤稿選擇」，進入步驟 10；否則進入步驟 9。
9. `WRITE` 回報「潤稿依賴受阻」，列出預檢錯誤或不可用的工具與補齊方式，然後停止；不寫草稿或筆記，不搜尋全域替代品。
10. `THINK` 依「素材輸入」列出讀者看完這一節能解釋、判斷或完成的事，建立「收穫清單」。
11. `READ` 規劃文章時，讀取 `rules/選材規劃-格式規範.md` 的所有 Rule，建立規劃檢查清單。
12. `THINK` 依「收穫清單」與已載入的規劃檢查清單，決定篇幅、是否納入操作步驟與提示詞、1～3 個關鍵字候選與標題。
13. `CHECK` 逐條驗證規劃檢查清單；未通過時修正規劃。

完成條件：已有通過預檢的潤稿選擇、收穫清單與通過規劃檢查清單的文章規劃。

## Phase 2 -- 查證關鍵字並記錄

1. `DELEGATE` 有搜尋工具時，對每個關鍵字候選查詢 Google 搜尋結果頁，記錄前幾名結果的內容類型與課程可回答的缺口；沒有搜尋工具時，將查證狀態標為「未查證」。
2. `READ` 寫入收穫紀錄時，讀取 `templates/notes.md` 與 `templates/notes.example.md`，建立「收穫紀錄樣板組」。
3. `WRITE` 依已載入的「收穫紀錄樣板組」，將收穫清單、篇幅與型態判定、關鍵字候選與查證狀態寫入輸出位置的 `notes.md`；每項收穫附逐字稿原句或時間碼。原句必須從素材逐字複製，保留原字詞、空白與標點；改寫放在「收穫」欄。
4. `DELEGATE` 單節模式下，在本 Skill 目錄執行 `uv run --script scripts/check_note_quotes.py --notes "<notes.md 絕對路徑>" --transcript "<逐字稿絕對路徑>"`，記錄退出碼與輸出為「引句檢查結果」。在其他工作目錄執行時，先將腳本路徑解析為絕對路徑。若原始逐字稿由對話提供，先將原文逐字保存為暫存檔供腳本讀取。若未安裝 `uv`，在已獲環境修改授權時依 [uv 官方說明](https://docs.astral.sh/uv/getting-started/installation/) 安裝後重試。
5. `CHECK` 單節模式必須取得「引句檢查結果」的退出碼 0 與通過訊息；缺少執行結果時返回步驟 4，比對失敗時進入步驟 6。工具受限、執行環境無法修復，或原始輸入無法讀取時進入步驟 7。通過後進入步驟 8；章級模式直接進入步驟 8。
6. `WRITE` 按「引句檢查結果」修正 `notes.md` 的來源欄。修正後返回步驟 4，對最新檔案重跑腳本。
7. `WRITE` 回報「引句未驗證」與受阻原因，提供草稿路徑並停止；不得進入 Phase 3 或回報正式交稿。
8. `CHECK` 核對 `notes.md` 的樣板格式與時間碼；章級模式另對照輸入的 `notes.md`，逐段檢查引句。發現差異時修正並返回步驟 4。

完成條件：`notes.md` 已寫入輸出位置，且通過格式與來源比對。單節模式必須有最新版本 `notes.md` 的腳本通過結果，才能進入 Phase 3。

## Phase 3 -- 寫文並驗證

1. `READ` 撰寫正文時，讀取 `rules/正文來源-格式規範.md` 的所有 Rule，建立正文檢查清單。
2. `WRITE` 依正文檢查清單與文章規劃產出完整工作草稿，保存為輸出位置的 `article.draft.md`。
3. `DELEGATE` 以「潤稿選擇」的絕對入口路徑讀取完整 Skill，依該 Skill 載入適用的同套件參考並執行潤稿。只提供工作草稿及編輯邊界：改表達；保留事實、例子、適用條件、確定程度、操作與提示詞；僅交回改寫全文或明確回報全文原樣保留。潤稿不得寫入逐字稿、筆記或其他檔案。
4. `CHECK` 已依指定 Skill 取得潤稿全文或明確的原樣保留結果時，進入步驟 6；否則進入步驟 5。
5. `WRITE` 回報潤稿受阻原因與工作草稿路徑，停止並保留現有正式文章。
6. `CHECK` 用原始素材逐條核對潤稿後正文檢查清單，留下 Rule 3 的工作紀錄，再依 Phase 1 的計數口徑實算篇幅。正文或篇幅未通過時修正並重查；每次修正後，對最新全文重新核對受影響的項目。計數工具不可用時，標為「未實測」。
7. `WRITE` 將通過終檢的全文寫入輸出位置的 `article.md`。
8. `WRITE` 回報 `article.md`、`notes.md` 的路徑、實測篇幅或「未實測」、文章型態、關鍵字查證狀態、潤稿 Skill 名稱與版本，以及潤稿結果。

完成條件：已依預檢選定的 Skill 完成潤稿；`article.md` 通過正文檢查清單，篇幅符合範圍或已標為「未實測」；已回報成果與潤稿結果。除 Phase 1 缺少輸入時外，執行中沒有向使用者提問。
