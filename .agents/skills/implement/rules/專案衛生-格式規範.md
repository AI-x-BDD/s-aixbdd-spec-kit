# Rule 1 - ignore 檔必須涵蓋任務實際引入的產物

- 專案是 git repository 時，任務引入的技術會產生下列產物時，必須在該任務完成前讓 `.gitignore` 涵蓋：依賴目錄、建置輸出、環境變數檔、日誌、測試與覆蓋率報告、工具快取、不在依賴目錄內的產生碼、OS 與編輯器雜檔。
- ignore 條目必須依產物的實際位置撰寫；子目錄專案的產物可以使用不帶前導 `/` 的模式。
- 不得忽略需要版控的檔案：migration、lock 檔、`.env.example` 等範例設定、工具設定檔，以及 spec 目錄中的文件。
- ignore 檔已存在時，必須只補缺少的條目，不得刪除或改寫既有條目。
- 只有專案中存在 Dockerfile 時，才可以建立 `.dockerignore`。
- 工具有自己的 ignore 機制（例如 Prettier 的 `.prettierignore`、ESLint flat config 的 `ignores`），且該工具的掃描範圍包含建置輸出或產生碼時，必須在該機制中排除這些產物。

## Good Example

- 診所掛號系統的後端以 Python、`uv` 與 Alembic 開發；任務引入虛擬環境、`.env` 與 pytest 快取後，在既有 `.gitignore` 後面補上對應條目，保留 `uv.lock` 與 `alembic/versions/` 進版控。

```gitignore
# 既有條目（保留）
.DS_Store

# T003 引入
backend/.venv/
__pycache__/
backend/.env
.pytest_cache/
htmlcov/
```

## Bad Example

- 同一個專案改寫了既有 `.gitignore`，並把 lock 檔、migration 與 `.env.example` 一起忽略，另外在沒有 Dockerfile 的情況下建立 `.dockerignore`。

```gitignore
*.lock
alembic/versions/
.env*
.venv/
```
