# SOP

## Phase 1 -- 選路與補資料

1. `THINK` 判斷任務是否為將一節課的逐字稿或字幕寫成可獨立閱讀的文章。適用時選 `course-article` 並進入步驟 3，其餘進入步驟 2。
2. `WRITE` 回報 Steve 第一版尚無該任務的交接路徑，結束。
3. `CHECK` 確認使用者提供的素材可讀。只有課名時，先在目前 repo 的上層找相鄰的私有課程 repo，再查是否能唯一定位該節素材。找到時進入步驟 6，否則進入步驟 4。
4. `WRITE` 只問「請給我這一節的逐字稿路徑，或貼上逐字稿。」
5. `CHECK` 收到來源後回到步驟 3；未收到時等待。
6. `CHECK` 確認使用者指定的私人輸出目錄，並查該目錄既有的 `article.md` 和 `notes.md`。若已指定且無舊成品，或已核准覆寫，記下執行前的檔案狀態並進入 Phase 2。沒給路徑或有成品未獲覆寫核准時進入步驟 7。
7. `WRITE` 缺路徑時只問「文章和筆記要存在哪個私有資料夾？」有舊成品時只問是否提供新位置或核准覆寫。
8. `CHECK` 收到路徑或覆寫核准後回到步驟 6；未收到時等待。

完成條件：已選定 `course-article`，且有可讀素材與已確認的私人輸出位置；否則已明確停在缺項或無適用路徑。

## Phase 2 -- 交接課程文章

1. `DELEGATE` 由本 `SKILL.md` 所在目錄解析同一工作樹同側的 `../course-article/SKILL.md`，載入後依其 SOP 執行。交接本次任務目標、素材與輸出目錄的絕對路徑、預期 `article.md` 和 `notes.md`，以及以下回傳要求：本次兩檔路徑、引句檢查結果、對應本次成稿的來源終檢結果、篇幅、關鍵字候選及查證狀態。受阻時回傳原因與已留下的檔案。寫作、篇幅選擇和潤稿都依子 Skill；貼在對話中的逐字稿依子 Skill 處理，保留供本次查核的同一份私人暫存原文。

完成條件：已取得 `course-article` 對本次任務的產物回傳或受阻回傳。

## Phase 3 -- 核對與收件

1. `CHECK` 查看指定位置的兩份檔案及回傳結果。核對兩檔屬於本次任務、正文來源終檢對應目前版本、篇幅與關鍵字查證狀態已有回報；篇幅「未實測」依子 Skill 規則保留。若有可讀筆記與原文，進入步驟 2；否則直接進入步驟 3。
2. `DELEGATE` 使用 `course-article` Phase 2 指定的引句檢查腳本 `check_note_quotes.py` 核對目前的筆記與交接時的同一份逐字稿。以絕對路徑執行 `uv run --script "<course-article 的檢查腳本>" --notes "<本次 notes.md>" --transcript "<本次逐字稿>"`，保留退出碼與輸出。
3. `CHECK` 本次兩檔、正文來源終檢及回報欄位齊全，且筆記引句取得通過結果時，進入步驟 4。若是已知檔案或檢查結果缺漏、引句不符或正文終檢沒通過，且 `course-article` 能處理、尚未退回，進入步驟 5。已退回、工具受阻或需要使用者補資料時，進入步驟 6。
4. `WRITE` 交付本次兩檔的路徑及檢查結果，然後結束。關鍵字標為「未查證」時，說明它們是候選、搜尋價值仍待查證；其餘檢查通過即可交稿。
5. `DELEGATE` 只退回 `course-article` 一次。指出失敗項及位置，要求修正或補查後回傳證據。引句不符時只修該引句、重跑比對；保留已通過的正文，尚無正文時待引句通過再接續原 SOP。將退回次數記為一次，回到步驟 1。
6. `WRITE` 回報未交稿、具體原因及目前留下的檔案，停止。只有使用者能補齊的必要資料缺失時，提問該項並等待；工具受阻時說明工具問題。

完成條件：本次成果已查核並交付，或已停止並說明受阻原因或待補項目。退回總數最多一次。
