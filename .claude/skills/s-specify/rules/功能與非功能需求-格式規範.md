# Rule 1 - FR 與 NFR 必須依需求性質區分並以可驗證的 MUST 陳述

- FR 必須描述系統必須提供的功能，或系統對使用者操作必須產生的反應。
- NFR 必須描述系統運作時須滿足的限制或品質，例如效能、可用性、易用性、語系或安全。
- 每條 FR 與 NFR 必須以「必須 (MUST)」陳述，並包含可驗證的條件。

## Good Example

- 拖放排序是功能，列為 FR；回饋延遲是運作品質，列為 NFR，並給出可驗證的門檻。

```markdown
- **FR-006**: 使用者必須 (MUST) 能夠在主頁面上透過拖放手勢重新排列相簿內照片的顯示順序。
- **NFR-002**: 從放開照片到畫面完成重新排版，視覺回饋延遲必須 (MUST) 低於 100 毫秒。
```

## Bad Example

- 拖放排序是功能卻被列為 NFR；另一條 FR 只描述感受，沒有可驗證的條件。

```markdown
- **NFR-002**: 使用者可以拖放重新排列照片。
- **FR-006**: 系統要讓整理照片的過程很好用。
```

# Rule 2 - 需求必須歸屬到主要服務的使用者故事

- 只服務單一使用者故事的需求，必須列在該故事底下。
- 被多個故事間接使用、但主要服務其中一個故事的需求，應歸到該故事。
- 只有無法歸屬單一故事，或明確約束多個故事的需求，才可以列在全域需求；全域需求不得作為未分類需求的預設位置。
- 每條需求必須只出現在一個位置，不得同時列在故事底下與全域需求。

## Good Example

- 平鋪預覽只服務「平鋪式預覽」故事，列在該故事底下；相簿不可巢狀同時約束「建立相簿」與「拖放整理」兩個故事，列在全域需求。

| 需求 | 服務的故事 | 位置 |
| ---- | ---------- | ---- |
| FR-005 平鋪式網格預覽照片 | 故事 2 | 故事 2 底下 |
| NFR-001 200 張照片 2 秒內呈現 | 故事 2 | 故事 2 底下 |
| FR-004 相簿維持單層、禁止巢狀 | 故事 1 的建立相簿、故事 3 的拖放 | 全域需求 |

## Bad Example

- 只屬於故事 2 的 NFR-001 被放進全域需求，FR-004 又同時出現在故事 1 底下與全域需求。

| 需求 | 服務的故事 | 位置 |
| ---- | ---------- | ---- |
| NFR-001 200 張照片 2 秒內呈現 | 故事 2 | 全域需求 |
| FR-004 相簿維持單層、禁止巢狀 | 故事 1、故事 3 | 故事 1 底下與全域需求 |

# Rule 3 - 需求編號必須唯一且不重排

- FR 必須使用 `FR-###`，NFR 必須使用 `NFR-###` 三位數格式。
- 同一份 spec 中，FR 與 NFR 的編號各自不得重複。
- 編號不得因需求在文件中的位置而重新排序；Clarifications 等處引用的編號必須指向同一條需求。

## Good Example

- 需求歸屬後保留原編號，故事 1 底下是 FR-001～FR-003、故事 2 底下是 FR-005，FR-004 在全域需求；Clarifications 的 `(FR-003)` 仍指向年月分組那一條。

```markdown
- Q: 相簿日期分組應該採用哪種時間粒度? (FR-003) → A: 依「年＋月」分組。

### User Story 2 - 相簿內照片平鋪式預覽 (Priority: P2)

- **FR-005**: 系統必須 (MUST) 在主頁面各相簿區塊預設內嵌展開平鋪式介面以預覽照片縮圖。
```

## Bad Example

- 依閱讀順序把故事 2 的 FR-005 重編為 FR-004，與全域需求的 FR-004 重複，原本指向 FR-005 的引用也失效。

```markdown
### User Story 2 - 相簿內照片平鋪式預覽 (Priority: P2)

- **FR-004**: 系統必須 (MUST) 在主頁面各相簿區塊預設內嵌展開平鋪式介面以預覽照片縮圖。

#### Functional Requirements

- **FR-004**: 系統必須 (MUST) 嚴格限制相簿為單層扁平結構。
```

# Rule 4 - 需求不得描述技術實作

- FR 與 NFR 必須描述系統要做到的行為或品質，不得指定框架、程式語言、資料庫或部署方式。
- 使用者輸入中的技術偏好不得改寫成 FR 或 NFR。

## Good Example

- 需求只要求狀態持久化保存，沒有指定如何保存。

```markdown
- **FR-009**: 系統必須 (MUST) 自動且持久化保存相簿分組、照片歸屬與自訂排列順序，重新開啟應用程式後狀態一致。
```

## Bad Example

- 同一條需求指定了資料庫與部署方式，屬於技術規劃階段的決策。

```markdown
- **FR-009**: 系統必須 (MUST) 以 Docker Compose 啟動 MySQL，保存相簿分組、照片歸屬與自訂排列順序。
```
