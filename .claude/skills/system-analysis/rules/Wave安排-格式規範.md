# Rule 1 - Wave 必須以技術端點為單位並依依賴排序

- 每個 Wave 必須以端點類型為單位安排；同一端點類型的所有介面必須放在同一個 Wave，不得拆到不同 Wave。
- 某個端點類型的分析需要使用另一個端點類型的分析結果時，視為依賴；被依賴的端點類型必須放在較前面的 Wave。後端介面的 request、response 或事件會傳遞資料庫介面保存的資料時，後端依賴資料庫，資料庫必須排在後端之前，讓後端以資料模型的欄位為準。
- 彼此沒有依賴的端點類型必須放在同一個 Wave 平行分析，不得只為了排出先後而拆成不同 Wave。
- 每個介面編號必須恰好出現在一個 Wave；不得遺漏介面，也不得在兩個 Wave 重複出現。
- 不得以需求部位為單位分 Wave，例如把同一功能的前端介面與後端介面放進同一個 Wave。

## Good Example

- 線上課程訂閱共盤出前端 F1–F2、後端 B1–B3、資料庫 D1、金流 P1。前端與金流沒有依賴，在 Wave 1 平行分析；資料庫依 Wave 1 確定的課程瀏覽與訂閱狀態推出資料結構，在 Wave 2；後端 API 依前端操作與金流付款結果設計，回傳的課程與訂閱欄位來自資料庫，在 Wave 3。每個介面恰好出現一次。

| Wave | 端點類型 | 涵蓋介面 |
| ---- | -------- | -------- |
| 1 | 前端、金流 | F1、F2；P1 |
| 2 | 資料庫 | D1 |
| 3 | 後端 | B1、B2、B3 |

## Bad Example

### Example 1

- 同一份盤點，Wave 改依需求部位切成「課程瀏覽」與「訂閱結帳」，前端與後端的介面被拆到不同 Wave；資料庫 D1 沒有出現在任何 Wave。

| Wave | 需求部位 | 涵蓋介面 |
| ---- | -------- | -------- |
| 1 | 課程瀏覽 | F1、B1 |
| 2 | 訂閱結帳 | F2、B2、B3、P1 |

### Example 2

- 同一份盤點，Wave 2 寫「後端、資料庫（2 個 Sub-agent 平行分析）」，排序理由寫「彼此沒有依賴」，但後端回傳的訂閱狀態是資料庫保存的欄位，後端應依賴資料庫，資料庫必須排在後端之前。

```markdown
**Wave 2：後端、資料庫（2 個 Sub-agent 平行分析）**

- 涵蓋介面：B1、B2、B3；D1
- 排序理由：後端與資料庫彼此沒有依賴，所以放在同一個 Wave。
```

# Rule 2 - Wave 區塊必須寫出涵蓋介面、依賴與排序理由

- 每個 Wave 必須寫成一個區塊，標題必須是 `**Wave N：<端點類型>、<端點類型>**`，`N` 從 1 連續編號。
- Wave 有兩個以上端點類型時，標題後必須加「（<數量> 個 Sub-agent 平行分析）」，數量等於該 Wave 的端點類型數；只有一個端點類型時不得加註。
- Wave 1 的區塊必須依序列出「涵蓋介面」與「排序理由」兩項。
- 第 2 個以後的 Wave 必須依序列出「涵蓋介面」、「依賴」與「排序理由」三項；「依賴」必須指出依賴前面哪個 Wave 的哪些結果。
- 「排序理由」必須說明這個 Wave 排在此位置的原因，同一 Wave 有多個端點類型時，必須說明它們彼此沒有依賴的原因。

## Good Example

- 線上課程訂閱的三個 Wave 都有標題；Wave 1 有兩個端點類型，加註 Sub-agent 數，只有涵蓋介面與排序理由；Wave 2、Wave 3 只有一個端點類型，不加註，並寫出依賴前面哪個 Wave 的哪些結果。

```markdown
**Wave 1：前端、金流（2 個 Sub-agent 平行分析）**

- 涵蓋介面：F1、F2；P1
- 排序理由：US1、US2 都從使用者在課程頁的操作開始，前端先確定操作，後端才知道要提供哪些 API；金流只需要查閱 Stripe 的結帳與 Webhook 文件，和前端分析沒有依賴，所以平行進行。

**Wave 2：資料庫**

- 涵蓋介面：D1
- 依賴：資料庫依 Wave 1 確定的課程瀏覽與訂閱狀態推出資料結構。
- 排序理由：後端回傳的課程與訂閱欄位來自資料庫，資料庫先確定欄位，後端才能以資料模型為準；資料庫只依賴 Wave 1，所以排在 Wave 2。

**Wave 3：後端**

- 涵蓋介面：B1、B2、B3
- 依賴：後端依 Wave 1 的前端操作與金流付款事件，以及 Wave 2 的資料模型欄位設計 API。
- 排序理由：後端同時依賴 Wave 1 與 Wave 2 的結果，必須排在最後。
```

## Bad Example

- 同一份 3 個 Wave，Wave 1 有兩個端點類型卻沒有加註 Sub-agent 數、沒有排序理由；Wave 3 沒有寫依賴 Wave 2 的哪些結果。

```markdown
**Wave 1：前端、金流**

- 涵蓋介面：F1、F2；P1

**Wave 2：資料庫**

- 涵蓋介面：D1
- 依賴：資料庫依 Wave 1 確定的課程瀏覽與訂閱狀態。
- 排序理由：後端回傳的欄位來自資料庫，資料庫先確定欄位。

**Wave 3：後端**

- 涵蓋介面：B1、B2、B3
- 依賴：後端依 Wave 1 的結果設計 API。
- 排序理由：後端要等前面的 Wave。
```
