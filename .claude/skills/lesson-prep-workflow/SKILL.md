# SOP

共同存檔契約：每個WRITE先保存成果，再依已載入的「接續檢查清單」及「進度樣板組」登記progress。委派回傳由下一WRITE或共用出口登記，對應CHECK驗證前只列待核對，驗證後才更新完成狀態。等待、失敗及完成均先走Phase1步驟9、10再停止／返回。只有工作位置尚缺時，Phase1步驟5依樣板展示暫存紀錄於對話，步驟6停止，取得位置再落檔。

## Phase 1 -- 取得素材與接續狀態

1. `READ` 使用者需求、指定素材與大綱（若有）；接續時讀取指定目錄 progress.md、待辦問題、已收到回覆及其連結的採用成果，建立「工作輸入」。
2. `READ` `rules/接續與交付-格式規範.md` Rule 1、2，建立「接續檢查清單」。
3. `THINK` 依「工作輸入」與「接續檢查清單」決定工作位置、缺項與「接續動作」；優先處理有效版本的待辦回覆，版本失效只退受影響關卡。無待辦時，新增或修訂素材走 Phase 2 收穫；作者要求章級／重新評估、已讀範圍擴大或修正影響既有判斷時走 Phase 2 決策；規劃接續走 Phase 2 委派；寫稿／作者清單／定稿走 Phase 3；社群／回顧走 Phase 4；明確能力交付請求走 Phase 5。缺工作位置時標記「位置待補」，繼續步驟4、5展示缺項。
4. `READ` `templates/progress.md` 與 `templates/progress.example.md`，建立「進度樣板組」。
5. `WRITE` 依「接續檢查清單」與「進度樣板組」保存本次接續紀錄；有缺項時展示所缺輸入及取得方式。後續每個 WRITE 與委派回傳的成果登記均使用這兩個載入結果。
6. `CHECK` 紀錄不符「接續檢查清單」或「進度樣板組」時返回步驟5；缺項已補齊時返回步驟1；位置仍缺時停止，其他缺項經步驟9保存等待後停止；齊備時繼續步驟7。
7. `READ` 僅新增或修訂來源時，讀取 `templates/source.md` 與 `templates/source.example.md`，建立「來源樣板組」。
8. `WRITE` 有來源變更時依「來源樣板組」保存 source；其餘保留原成果。依「接續檢查清單」及「進度樣板組」登記後進入「接續動作」對應 Phase 的第 1 步。
9. `WRITE` 僅由完成／等待／失敗出口呼叫：依「接續檢查清單」及「進度樣板組」保存尚未登記的成果、待辦問題、展示版本、實際回覆、狀態與下一動作，交付路徑及缺口。
10. `CHECK` 核對成果與進度可讀且符合「接續檢查清單」及「進度樣板組」；本次有source寫入時另驗「來源樣板組」。進度失敗返回步驟9，source失敗返回步驟8修正；通過後依呼叫出口指定停止或返回呼叫者。

完成條件：素材、指定位置、採用版本與下一個待執行動作均可由進度找到。

## Phase 2 -- 累積收穫與評估成文

1. `READ` 收穫／決策模式讀本次素材及存在的收穫、索引與決策；無新素材的決策模式讀已存素材；純規劃接續只讀該文章的依賴版本、研究與確認，建立「累積輸入」。
2. `READ` 收穫模式讀 `rules/收穫與成文-格式規範.md` Rule 1、2及 `../lesson-prep-writing/rules/證據標示-格式規範.md` 所有 Rule，建立「收穫檢查清單」；決策模式或委派模式直接進步驟 7或10。
3. `READ` `templates/learning-record.md` 與 `templates/learning-record.example.md`，建立「收穫樣板組」。
4. `WRITE` 依「收穫檢查清單」與「收穫樣板組」保存本次各節收穫。
5. `READ` `templates/learning-index.md` 與 `templates/learning-index.example.md`，建立「索引樣板組」。
6. `WRITE` 依「收穫檢查清單」與「索引樣板組」保存跨節索引版本。
7. `CHECK` 收穫模式逐條驗證「收穫檢查清單」與兩組樣板；失敗返回步驟 4；只累積時經 Phase 1 步驟 9 交付後停止；其餘及決策模式繼續。
8. `READ` `rules/收穫與成文-格式規範.md` Rule 3、4及 `../lesson-prep-writing/rules/證據標示-格式規範.md` 所有 Rule，建立「成文檢查清單」；同時讀 `templates/content-decision.md`、`templates/content-decision.example.md`，建立「成文評估樣板組」。
9. `WRITE` 依「累積輸入」、「成文檢查清單」與「成文評估樣板組」保存並展示內容價值建議；有效既有建議及回覆直接沿用，待決定時保存問題。
10. `CHECK` 純規劃接續且有效成文決定存在時直接進步驟11，缺決定返回步驟8。其他模式核對「成文檢查清單」與樣板，失敗或作者要求調整返回步驟9；選暫存或未回覆時經 Phase 1 步驟9保存決定／等待後停止；選推進時繼續。
11. `DELEGATE` 載入並執行同一 skills-root 的 lesson-prep-writing，交付「規劃交接」：來源模式 F、output-root、實際文章目錄、來源版本與可讀素材、收穫／索引／決策採用版本、已確認範圍及其輸入版本、讀者研究及搜尋比較版本或缺項、搜尋導向開關、作者目前資源、終點（選題／大綱）、講師／目標讀者／編輯／紅隊／文件類型編輯、待辦問題及本次回覆。要求回傳狀態、採用方向／大綱／檢查路徑與輸入版本、確認、缺口、待辦動作及回覆。
12. `CHECK` 核對回傳欄位及可讀成果；缺欄位退回步驟 11補回傳，工具失敗或等待作者／資料時經 Phase 1 步驟 9保存後停止；暫不成文返回步驟 8；僅規劃任務完成時經 Phase 1 步驟 9交付後停止；全文任務取得有效確認大綱及採用後檢查時進 Phase 3，其餘經 Phase 1 步驟 9保存缺口後停止。

完成條件：收穫及來源已保存，成文決定可追溯；進入全文的文章已有規劃成果與作者確認。

## Phase 3 -- 寫稿、用途檢查與定稿

1. `READ` 採用大綱、來源、讀者研究與作者清單；接續定稿時另讀受檢初稿、檢查、採用項及確認版本。
2. `READ` `rules/成稿與發表-格式規範.md` Rule 1、`../lesson-prep-writing/rules/備課-格式規範.md` 與 `../lesson-prep-writing/rules/證據標示-格式規範.md` 所有 Rule，建立「成稿檢查清單」。
3. `CHECK` 依「成稿檢查清單」及「接續檢查清單」核對依賴；缺有效讀者研究／規劃時以規劃接續模式返回 Phase 2 步驟 1。待定稿採用且版本有效時先進步驟7～9載入並核對既有檢查，再接步驟10；其他有效作者清單已全通過，且其開頭與小標選用紀錄符合本次成稿檢查時進步驟6；其餘進步驟4。
4. `WRITE` 依「成稿檢查清單」選定開頭與小標用語，將選用理由及來源與寫稿前作者清單一起展示並保存。清單涵蓋成果及範圍、每段來源或教學設計、必要練習取捨、作者認同的一句重點、讀者原詞來源或不適用理由、稿內待補證據補齊或刪除決定、文類與必要解說、可驗證的成果檢核。依「接續檢查清單」沿用有效確認，只問尚缺及受影響項。
5. `CHECK` 作者逐項通過時繼續；修改大綱時以規劃接續模式返回 Phase 2 步驟 1；其餘經 Phase 1 步驟 9保存等待後停止。搜尋用途待補依用途狀態保留，稿內待補事實依作者清單及證據檢查處理。
6. `WRITE` 依採用大綱、有效作者清單中的選用紀錄與「成稿檢查清單」另存完整初稿。
7. `READ` `templates/publication-check.md` 與 `templates/publication-check.example.md`，建立「成稿檢查樣板組」。
8. `WRITE` 依「成稿檢查清單」與「成稿檢查樣板組」保存初稿的模擬試讀、逐用途結果及修改建議；接續有效既有檢查時只登記沿用。
9. `CHECK` 逐條驗證檢查紀錄符合清單及樣板；紀錄缺項返回步驟 8；稿件缺口保留在結果中，繼續作者選擇。
10. `WRITE` 展示並保存待採用修改、各用途結果與缺口，請作者選擇修改及確認定稿；已收到對應版本的明確回覆時沿用。
11. `CHECK` 採用範圍及定稿確認明確時繼續；要求新修改時返回步驟 6；其餘經 Phase 1 步驟 9保存等待後停止。
12. `WRITE` 只套用作者採用項，另存定稿及採用紀錄。
13. `CHECK` 比對定稿差異；超出或漏套採用項時返回步驟 12；需擴大採用範圍時返回步驟 10，不自行增加修改。
14. `WRITE` 依「成稿檢查清單」與「成稿檢查樣板組」另存定稿對應的逐用途結果，重查受影響教學、證據及提示詞項，未受影響項連回有效證據；保留初稿檢查歷史。
15. `CHECK` 檢查紀錄不完整返回步驟 14；稿件仍有缺口且需新取捨返回步驟 10；作者已明確保留的缺口如實交付。核對通過且另有社群／回顧任務時進 Phase 4；其餘經 Phase 1 步驟 9交付全文及各用途狀態後停止。

完成條件：完整文章及逐用途結果可讀，作者採用修改與定稿版本可追溯。

## Phase 4 -- 社群與回顧

1. `READ` 社群任務讀採用稿、讀者卡、平台及已提供的網址／經驗；回顧任務讀實際日期、收到的成效與原話、原假設及存在的基準。接續時讀平台草稿、選定開頭與確認版本。
2. `READ` 讀取 `../lesson-prep-writing/rules/證據標示-格式規範.md` 所有 Rule；社群讀 `rules/成稿與發表-格式規範.md` Rule 2，回顧讀同檔 Rule 3，建立「發表檢查清單」。
3. `THINK` 依「發表檢查清單」判定適用輸入；只有回顧時進步驟 8；已有有效社群選擇時進步驟 5；缺核心稿件／平台時經 Phase 1 步驟 9保存等待後停止；缺網址或經驗只標待補、略過無據內容。
4. `WRITE` 依「發表檢查清單」保存並展示平台草稿及三種開頭。
5. `CHECK` 作者選定開頭及確認內容時繼續；要求修改返回步驟 4；未選定經 Phase 1 步驟 9保存等待後停止。
6. `WRITE` 另存作者確認的各平台定稿。
7. `CHECK` 依「發表檢查清單」核對定稿與採用範圍；套用錯誤返回步驟 6；需新修改返回步驟 4；只要求社群時經 Phase 1 步驟 9交付後停止。
8. `WRITE` 依「發表檢查清單」保存當週資料、判讀及下一次驗證建議；缺資料保存待補。
9. `CHECK` 逐條驗證「發表檢查清單」適用項；紀錄不符返回步驟8；缺實際資料保留受阻狀態。若建議修改Skill規則，只交建議，修改留工程流程另核准。
10. `WRITE` 依「接續檢查清單」與「進度樣板組」保存成果後轉 Phase 1 步驟 9交付並停止。

完成條件：本次要求的社群或回顧成果已保存；作者選擇、實際資料與待補可追溯。

## Phase 5 -- 準備能力交付紀錄

1. `READ` 明確指定的候選交付範圍、來源版本、可攜帶驗證摘要、現有紀錄及本次獲准寫入位置。
2. `READ` `rules/接續與交付-格式規範.md` Rule 3，建立「交付檢查清單」。
3. `THINK` 依「交付檢查清單」決定候選 payload 與紀錄位置；預設在指定 staging 下兩個 Skill 目錄各放 package-record.md。若要求直接寫來源兩目錄，須有該寫入範圍授權；已有紀錄須有更新授權及備份位置，缺任一項經 Phase 1 步驟 9保存等待後停止。
4. `READ` `templates/package-record.md` 與 `templates/package-record.example.md`，建立「交付紀錄樣板組」。
5. `WRITE` 依「交付檢查清單」及「交付紀錄樣板組」保存兩份相同候選紀錄。
6. `CHECK` 逐條驗證「交付檢查清單」及樣板；使用 `shasum -a 256` 查可讀 payload、來源有 Git 時使用 `git rev-parse HEAD`；比對兩份紀錄一致。內容錯誤返回步驟 5；工具或依據缺失列為待補。
7. `WRITE` 保存查核結果、可攜帶驗證摘要及待補；未完成驗收時保留候選／未驗證狀態。
8. `CHECK` 紀錄可讀且兩份一致時經 Phase 1 步驟 9交付後停止；不一致返回步驟 7。安裝、覆蓋其他副本及公開發佈留另行授權作業。

完成條件：候選交付範圍及來源紀錄可供安裝作業使用，缺項與驗證狀態明列。
