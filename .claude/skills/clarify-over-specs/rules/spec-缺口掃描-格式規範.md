# Rule 1 - 必須以 10 類分類表掃描整份 spec

- 掃描必須逐一檢查下表 10 個分類，每個分類必須標出 Clear、Partial 或 Missing 其中一種初始狀態。
- 每個候選缺口必須標出它屬於下表的哪一個分類；提問時的分類名稱必須使用下表「分類」欄的中文名稱。

| 分類 | 英文原名 | 檢查項目 |
| ---- | -------- | -------- |
| 功能範圍與行為 | Functional Scope & Behavior | 核心使用者目標與成功標準、明確的範圍排除、使用者角色區分 |
| 領域與資料模型 | Domain & Data Model | 實體、屬性與關聯、識別與唯一性規則、生命週期與狀態轉換、資料量與規模假設 |
| 互動與 UX 流程 | Interaction & UX Flow | 關鍵使用者旅程與順序、錯誤／空白／載入狀態、無障礙或在地化 |
| 非功能品質屬性 | Non-Functional Quality Attributes | 效能、擴充性、可靠度與可用性、可觀測性、安全與隱私、法規遵循 |
| 整合與外部依賴 | Integration & External Dependencies | 外部服務與失敗模式、資料匯入匯出格式、協定與版本假設 |
| 邊界情境與錯誤處理 | Edge Cases & Failure Handling | 負面情境、流量限制、衝突處理（例如同時修改） |
| 限制與取捨 | Constraints & Tradeoffs | 技術限制、明確的取捨或被捨棄的方案 |
| 術語與一致性 | Terminology & Consistency | 標準術語、應避免的同義詞或舊稱 |
| 完成訊號 | Completion Signals | 驗收標準的可測性、可量測的完成指標 |
| 雜項與佔位 | Misc / Placeholders | TODO 與未決事項、缺乏量化的模糊形容詞 |

- 掃描範圍必須是整份 spec，不得只看 `NEEDS CLARIFICATION` 標記；段落之間的矛盾、缺乏量化的形容詞、標為（推定）的需求與 Assumptions 都必須檢查。

## Good Example

- spec 沒有任何 `NEEDS CLARIFICATION` 標記，掃描仍從段落矛盾、推定需求與模糊形容詞找出缺口，並標出分類。

| 候選缺口 | 位置 | 分類 |
| -------- | ---- | ---- |
| FR-004 寫開課 24 小時前可取消，Edge Cases 寫 12 小時內不可取消 | FR-004、Edge Cases | 邊界情境與錯誤處理 |
| 「每人同時最多預約 3 堂」只是推定 | Assumptions、FR-002 | 功能範圍與行為 |
| NFR 寫「預約要即時」，沒有門檻 | NFR-001 | 非功能品質屬性 |

## Bad Example

- 同一份 spec 因為沒有 `NEEDS CLARIFICATION` 標記，掃描結論是沒有缺口，10 個分類也沒有逐一標出狀態。

情境：

1. 搜尋 `NEEDS CLARIFICATION`，沒有結果。
2. 結論：「spec 沒有待澄清項目。」

# Rule 2 - 實作問題必須記為 Deferred，不得提問

- 只與實作方法、技術選型（框架、資料庫、雲端服務、函式庫）或任務拆解有關的缺口，不得列入提問，必須記為 Deferred 並寫出理由。
- 不先決定技術限制就無法確定功能行為或驗收標準時，可以列入提問，提問內容必須是對使用者可見的行為或限制，不得是技術方案的比較。

## Good Example

- 「想用 Redis 做名額鎖」是技術選型，記為 Deferred；「同時搶最後一個名額時誰成功」影響使用者可見的結果，列入提問。

| 候選缺口 | 處理 | 理由 |
| -------- | ---- | ---- |
| Input 寫「名額鎖想用 Redis」 | Deferred | 屬於技術選型，留到技術規劃 |
| 兩位會員同時預約最後一個名額時，誰預約成功 | 列入提問 | 改變驗收情境與 Edge Cases |

## Bad Example

- 同一份 spec 把技術選型列入提問，要使用者在需求階段比較資料庫方案。

情境：

1. 提問：「名額鎖要用 Redis、PostgreSQL row lock，還是 in-memory lock？」
2. 回報的 Deferred 沒有列出任何技術選型項目。

# Rule 3 - 提問必須依「影響 × 不確定性」排序

- 候選缺口必須依「影響 × 不確定性」由高到低排序：影響指答案會改變使用者故事切分、核心流程、資料模型、驗收標準或不可逆決策的範圍；不確定性指 spec 中沒有線索或線索互相矛盾的程度。
- 還有高影響且未解決的分類時，不得先排入兩個以上屬於其他分類的低影響缺口。
- 答案不會改變需求、驗收或使用者體驗的缺口，不得列入提問。

## Good Example

- 會改變核心流程的矛盾與狀態生命週期排在前面，措辭問題不列入提問。

| 順序 | 候選缺口 | 分類 | 排序理由 |
| ---- | -------- | ---- | -------- |
| 1 | 取消期限在 FR-004 與 Edge Cases 互相矛盾 | 邊界情境與錯誤處理 | 改變核心流程與驗收情境，線索互相矛盾 |
| 2 | 預約的狀態（已預約、候補、已取消、已出席）未定義 | 領域與資料模型 | 改變資料模型與多個故事 |
| — | 預約成功訊息要寫「預約完成」還是「預約成功」 | 雜項與佔位 | 不改變需求與驗收，不列入 |

## Bad Example

- 同一份 spec 先問兩個措辭與顏色問題，取消期限的矛盾與預約狀態卻排在後面。

| 順序 | 候選缺口 | 分類 |
| ---- | -------- | ---- |
| 1 | 預約成功訊息的措辭 | 雜項與佔位 |
| 2 | 課表的主色 | 互動與 UX 流程 |
| 3 | 取消期限在 FR-004 與 Edge Cases 互相矛盾 | 邊界情境與錯誤處理 |

# Rule 4 - 已在 Clarifications 回答的問題不得重問

- `## Clarifications` 已有 `Q → A` 回答的問題，不得再列入提問。
- 新的候選缺口與既有 `Q → A` 決定同一件事時，即使措辭不同，也必須視為已回答。
- 既有答案與 spec 其他段落矛盾時，必須依既有答案處理矛盾，不得重新提問同一件事。

## Good Example

- 既有紀錄已決定同時預約上限，掃描不再提問；只把仍未決定的候補規則列入。

情境：

1. 既有紀錄：`- Q: 會員可以同時預約幾堂課? (FR-002) → A: 同時最多預約 3 堂未開始的課程。`
2. 候選缺口：「每位會員的預約上限是多少？」判定為已回答，不列入。
3. 候選缺口：「額滿後取消的名額如何處理？」沒有紀錄，列入提問。

## Bad Example

- 同一個預約上限換了措辭再問一次，使用者必須重新回答已決定的問題。

情境：

1. 既有紀錄：`- Q: 會員可以同時預約幾堂課? (FR-002) → A: 同時最多預約 3 堂未開始的課程。`
2. 提問：「每位會員最多可以持有幾筆有效預約？」

# Rule 5 - 最終狀態必須依處理結果判定

- 結束時，每個分類必須依下表判定一種最終狀態；同一分類有多個缺口時，依未處理缺口中最需要注意的狀態判定，順序為 Deferred、Outstanding、Resolved、Clear。

| 最終狀態 | 判定條件 |
| -------- | -------- |
| Resolved | 初始為 Partial 或 Missing，本次的回答已解決該分類所有列入提問的缺口 |
| Deferred | 有缺口因屬實作類、超過題數或使用者結束提問而未處理 |
| Clear | 初始為 Clear，本次沒有發現缺口 |
| Outstanding | 仍為 Partial 或 Missing，但剩餘缺口影響低、不列入提問 |

- 每個 Deferred 與 Outstanding 的分類必須列出未處理的缺口與理由。

## Good Example

- 每個分類只有一種最終狀態，Deferred 與 Outstanding 都列出項目與理由。

| 分類 | 最終狀態 | 未處理的缺口與理由 |
| ---- | -------- | ------------------ |
| 邊界情境與錯誤處理 | Resolved | — |
| 領域與資料模型 | Deferred | 預約狀態生命週期：已達 5 題上限 |
| 限制與取捨 | Deferred | 名額鎖的技術選型：屬實作類，留到技術規劃 |
| 雜項與佔位 | Outstanding | 成功訊息措辭：影響低 |
| 術語與一致性 | Clear | — |

## Bad Example

- 同一情境中，未處理的預約狀態被標成 Resolved，技術選型被標成自訂的「略過」，Deferred 項目沒有理由。

| 分類 | 最終狀態 | 未處理的缺口與理由 |
| ---- | -------- | ------------------ |
| 領域與資料模型 | Resolved | — |
| 限制與取捨 | 略過 | — |
| 雜項與佔位 | Deferred | — |
