# Rule 1 - 正文只能使用逐字稿的內容

- 正文的定義、比喻、例子、數字與專有名詞，必須在輸入的逐字稿中找得到對應內容。
- 逐字稿沒有出現的案例、產品名稱與表格，不得進入正文。
- 確實需要補充逐字稿沒有的內容時，必須在該處以「補充」標示，並寫明補充的理由。

## Good Example

- 文章保留講師的書本目錄比喻，每個說法都對應逐字稿原句；逐字稿沒有交代的對應關係以「補充」標示並寫明理由。

情境：

- 逐字稿：講師說「索引就像書後面的目錄，你不用翻完整本書，直接查頁碼就能找到內容」。
- 正文：「資料庫索引就像書後的目錄：查到頁碼，就能直接翻到需要的內容。」
- 正文接著寫：「補充：在這個比喻中，頁碼對應資料的位置。理由：說明目錄為什麼能幫助讀者直接找到內容。」

## Bad Example

- 文章加入逐字稿沒有的訂單案例、數字與比較表，也沒有任何「補充」標示與理由。

情境：

- 逐字稿：同上，只有書本目錄的比喻。
- 正文：「假設電商有 100 萬筆訂單，沒有索引時查詢要 3 秒，加上索引後降到 0.01 秒。」後面附一張「有索引／沒有索引」的比較表。
- 訂單案例、100 萬筆、3 秒、0.01 秒與比較表都不在逐字稿，也沒有「補充」標示。

# Rule 2 - 正文直接解說觀念

- `article.md` 的正文必須直接解說觀念、例子與操作。
- 正文不得出現授課者姓名、用「講師」等稱呼指涉授課者，或用「他提到」等轉述授課者的句型。
- 改寫時必須保留原文的確定程度與適用條件；預測、推測及個人判斷仍須用「可能」、「一種看法是」等文字表達。
- 正文出現「最」、「唯一」、「通常」、「必須」等表示排序、頻率、範圍或必要性的措辭時，必須回查來源，核對比較的是什麼、適用範圍有多大；有落差時修回原意。例如「最嚴重的問題之一」必須保留嚴重程度及「之一」的範圍。
- 移除正文中的授課者資訊時，不得改動 `notes.md` 內用於追溯來源的原句或時間碼。

## Good Example

- 直接描述可能的發展，並保留原句的不確定性。

情境：逐字稿說「我猜未來可能會有更多專用 Agent。」

```text
未來可能會有更多專用 Agent。
```

## Bad Example

- 同一段逐字稿被寫成授課者轉述，而且把預測改成確定會發生的事。

```text
講師表示，未來一定會有更多專用 Agent。
```
