# Rule 1 - 和鎖定項目衝突的需求不得寫入憲法

- 鎖定項目是下游 Skill 或目標 Skill 的檢查腳本依賴的結構，例如需求編號引用、介面編號、operation 的 tag 格式、任務 ID 與 Must Read 格式。
- 鎖定項目也包含目標 Skill 憲法載入步驟列出的不可覆寫項目。
- 「規則需求」會改變鎖定項目的結構時，不得寫入憲法，必須列入「拒絕清單」。
- 列入「拒絕清單」時，必須寫出衝突的結構與依賴該結構的 Skill 或腳本。

## Good Example

- 需求要把 OpenAPI 的 tag 改成資源名稱；該 tag 格式是下游 Skill 依賴的結構，因此列入「拒絕清單」並寫出依賴者。

情境：

1. 使用者要求：「OpenAPI 的 tag 改用資源名稱，例如 orders、products」。
2. 「目標 Skill 現況」顯示 `api-plan` 的每個 operation tag 為「介面編號 介面名稱」，`tasks` 依這個格式對應任務與介面。
3. 該需求列入「拒絕清單」，原因：衝突的結構是 operation 的 tag 格式，依賴者是 `tasks`。

## Bad Example

- 需求改變了下游依賴的 tag 格式，卻直接寫入憲法檔，也沒有回報依賴者。

情境：

1. 使用者要求：「OpenAPI 的 tag 改用資源名稱，例如 orders、products」。
2. 「目標 Skill 現況」顯示 `tasks` 依 tag 的「介面編號 介面名稱」格式對應任務與介面。
3. 在 `skills/api-plan/openapi.md` 新增 `# Rule 3 - tag 必須使用資源名稱`。
