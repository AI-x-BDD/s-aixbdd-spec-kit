# Rule 1 - 檢查範圍必須涵蓋目標 Skill 的部位與各 spec 目錄的產出物

- 檢查範圍必須是「落點檢查清單」決定的目標 Skill 與其產出物，再依該 Rule 的適用條件排除不適用的。
- Skill 部位必須包含 `SKILL.md` 中直接規定產出物內容的步驟、`rules/` 與 `templates/`。
- 產出物必須取自「spec 目錄清單」中的每個 spec 目錄。
- 程式碼產出物必須依該 spec 目錄的 `plan.md` 專案結構與 `tasks.md` 的檔案路徑定位。
- 不得讀取 `specs/001-photo-album-organizer/` 與 `specs/skill-engineering/`。

## Good Example

- 規則約束 `contracts/openapi.yaml`，檢查範圍包含 `api-plan` 的各部位與每個 spec 目錄的 `openapi.yaml`，並排除兩個不可讀取的目錄。

情境：

1. 新增 `skills/api-plan/openapi.md` 的 Rule 3「清單回應必須包含 `total`」。
2. 目標 Skill 是 `api-plan`；Skill 部位檢查 `SKILL.md` 規定回應內容的步驟、`rules/` 與 `templates/`。
3. 產出物檢查「spec 目錄清單」中每個 spec 目錄的 `contracts/openapi.yaml`。
4. `specs/001-photo-album-organizer/` 與 `specs/skill-engineering/` 不在檢查範圍內。

## Bad Example

- 只檢查一個 spec 目錄，略過 `templates/`，並讀取不可讀取的目錄。

情境：

1. 新增 `skills/api-plan/openapi.md` 的 Rule 3「清單回應必須包含 `total`」。
2. 只檢查 `specs/002-order-refund/contracts/openapi.yaml`，沒有檢查其他 spec 目錄。
3. 沒有檢查 `api-plan` 的 `templates/`。
4. 為了多找幾個產出物，讀取 `specs/skill-engineering/` 下的檔案。

# Rule 2 - 只有違反規則的內容才列為衝突

- 只有違反 Rule 的內容才可以列入衝突清單。
- 符合 Rule 的內容不得列入衝突清單。
- Rule 明定的例外成立時，不得列入衝突清單。
- 判定必須依該 Rule 的適用條件，不得套用 Rule 沒有寫出的要求。

## Good Example

- 三個產出物分別違反、符合與例外成立，只有違反的列為衝突。

情境：

1. 新增規則：「訂單狀態欄位必須使用 Enum；spec 明確要求自由文字時可以例外」。
2. 甲 spec 的 `data-model.dbml` 以 `varchar` 儲存訂單狀態，列入衝突清單。
3. 乙 spec 的 `data-model.dbml` 以 Enum 儲存訂單狀態，判定為符合，不列入衝突清單。
4. 丙 spec 的 `spec.md` 明確要求自由文字，資料模型使用 `varchar`，判定為例外成立，不列入衝突清單。

## Bad Example

- 例外成立的產出物被列為衝突，且套用了規則沒有寫出的要求。

情境：

1. 新增規則：「訂單狀態欄位必須使用 Enum；spec 明確要求自由文字時可以例外」。
2. 丙 spec 的 `spec.md` 明確要求自由文字，資料模型使用 `varchar`，卻列入衝突清單。
3. 乙 spec 的 Enum 值沒有使用大寫，也列入衝突清單；規則沒有要求大寫。

# Rule 3 - 結果必須分成檢查紀錄與衝突清單兩個表格，並標出處理 Skill

- 一致性檢查結果必須分成「檢查紀錄」與「衝突清單」兩個 Markdown 表格。
- 檢查紀錄的欄位必須是「路徑與部位｜憲法檔與 Rule 編號｜判定」，每個已檢查的 Skill 部位與產出物各佔一列。
- 目標 Skill 的 `SKILL.md`、`rules/`、`templates/` 必須各佔至少一列；目標 Skill 缺少的部位也必須列出，判定為「無法檢查」。
- 判定只能是「符合」、「例外成立」、「衝突」、「無法檢查」；「無法檢查」必須在同一格寫出 Rule 4 規定的原因。
- 檢查紀錄不得填處理 Skill。
- 衝突清單的欄位必須是「位置｜憲法檔與 Rule 編號｜說明｜處理 Skill」；沒有衝突時，表格下方寫「無」。
- 位置必須包含檔案路徑與部位：Rule 編號、樣板區段、Phase 與步驟，或產出物的段落。
- 處理 Skill 的對應必須如下表。

  | 衝突位置 | 處理 Skill |
  | --- | --- |
  | `spec.md` | `s-specify` 或 `clarify-over-specs` |
  | `research.md`、`techstack.md` | `technical-research` |
  | `plan.md` | `system-analysis` |
  | `contracts/` | `api-plan` |
  | `data/` | `data-plan` |
  | `ui/` | `ui-plan` |
  | `tasks.md` | `tasks` |
  | 程式碼 | `implement` |
  | 目標 Skill 的 `SKILL.md`、`rules/`、`templates/` | `skill-engineering` |

## Good Example

- 兩個表格的欄位固定；檢查紀錄每列都有憲法檔與 Rule 編號，目標 Skill 的三個部位各佔一列；衝突清單只列違反的項目，並填入處理 Skill。

情境：新增 `skills/data-plan/data-model.md` 的 Rule 2「訂單狀態欄位必須使用 Enum」。

檢查紀錄：

| 路徑與部位 | 憲法檔與 Rule 編號 | 判定 |
| --- | --- | --- |
| `.agents/skills/data-plan/SKILL.md` Phase 2 步驟 2 | `skills/data-plan/data-model.md` Rule 2 | 符合 |
| `.agents/skills/data-plan/rules/資料模型-格式規範.md` | `skills/data-plan/data-model.md` Rule 2 | 符合 |
| `.agents/skills/data-plan/templates/data-model.example.dbml` | `skills/data-plan/data-model.md` Rule 2 | 符合 |
| `specs/003-shop/data/data-model.dbml` 的 `orders` 資料表 | `skills/data-plan/data-model.md` Rule 2 | 衝突 |
| `specs/004-shop-v2/data/data-model.dbml` 的 `orders` 資料表 | `skills/data-plan/data-model.md` Rule 2 | 符合 |

衝突清單：

| 位置 | 憲法檔與 Rule 編號 | 說明 | 處理 Skill |
| --- | --- | --- | --- |
| `specs/003-shop/data/data-model.dbml` 的 `orders` 資料表 | `skills/data-plan/data-model.md` Rule 2 | `status` 欄位為 `varchar`，不是 Enum | `data-plan` |

## Bad Example

- 結果以自由條列寫出：檢查紀錄只列衝突項目、沒有 Rule 編號，也沒有列出目標 Skill 的部位；衝突清單的處理 Skill 填錯。

情境：新增 `skills/data-plan/data-model.md` 的 Rule 2「訂單狀態欄位必須使用 Enum」。

- 檢查紀錄：`specs/003-shop/data/data-model.dbml` 衝突；`data-plan` 的樣板符合。
- 衝突清單：`specs/003-shop/data/data-model.dbml`，`status` 欄位不符，處理 Skill `skill-engineering`。

# Rule 4 - 無法檢查的項目必須列出原因

- 無法檢查的項目必須列為「無法檢查」並寫出原因。
- 原因必須是下列其中一項：沒有任何 spec 目錄有該產出物、找不到路徑、讀取失敗、目標 Skill 不存在。
- 無法檢查的項目不得列為通過。
- 目標 Skill 缺少某個部位時，其他部位仍然必須檢查。
- 程式碼的指定路徑不存在時，必須寫「指定路徑不存在」，不得自行判斷為尚未實作。

## Good Example

- 程式碼路徑不存在，列為無法檢查；缺少 `templates/` 的 Skill，其他部位仍有檢查結果。

情境：

1. 新增 `skills/implement/code.md` 的 Rule 1「公開函式必須有型別註記」。
2. 甲 spec 的 `plan.md` 專案結構列出 `src/`，但 `src/` 不存在；檢查紀錄寫「無法檢查」，原因「指定路徑不存在」。
3. `implement` 沒有 `templates/`；檢查紀錄對 `templates/` 寫「無法檢查」，原因「找不到路徑」，`SKILL.md` 與 `rules/` 仍列出判定。

## Bad Example

- 路徑不存在被判為通過，且因為缺少一個部位而停止檢查其他部位。

情境：

1. 新增 `skills/implement/code.md` 的 Rule 1「公開函式必須有型別註記」。
2. 甲 spec 的 `plan.md` 專案結構列出 `src/`，但 `src/` 不存在；檢查紀錄寫「符合」。
3. `implement` 沒有 `templates/`；整個 Skill 部位的檢查停止，`SKILL.md` 與 `rules/` 沒有檢查結果。
