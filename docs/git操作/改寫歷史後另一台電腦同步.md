# 改寫歷史後，另一台電腦怎麼同步（2026-11-04）

## 背景

2026-11-04 用 `git filter-repo` 從全部 git 歷史移除了 2 個含有課程內容的筆記檔，並 force push 到 GitHub：

- `docs/tmp/後設反推：Artifact-First第四步.md`
- `docs/學習筆記/SDD流程與Analyze的定位.md`

改寫後，從 `891a5be` 開始的 commit 都換成新的 hash，5 個 tag 也改指向新的 commit。新的最新 commit 是 `2f5e831 feat(analyze): ...`。

另一台電腦還保留著舊歷史。新舊歷史的 commit hash 不同，git 會把它們當成兩條不同的歷史，所以**不能直接 `git pull`**：

- `pull` 用 merge：新舊歷史被合併，舊的 commit 和那 2 個檔都會留下。
- `pull` 用 rebase：舊的 commit 被接到新歷史後面，那 2 個檔會被加回來。
- 接著 `git push`，舊的 commit 就會回到 GitHub，前面的清除就白做了。

## 執行前：確認沒有東西會遺失

在 `git fetch origin` **之前**執行（此時 `origin/main` 還是舊的）：

```
git status
git log origin/main..main --oneline
```

- 兩個指令都沒有輸出：可以繼續。
- 有輸出：那台電腦有尚未提交的修改，或尚未 push 的 commit。先處理，不要執行下面的 reset。

這 2 個檔在舊歷史裡是被追蹤的，reset 後會從資料夾消失。要保留的話，先複製到 repo 外面，reset 後再放回 `docs/tmp/`（`docs/tmp/` 已被 `.gitignore` 排除，不會再被 commit）。

## 同步指令

```
git fetch origin
git reset --hard origin/main
git tag -l | xargs git tag -d
git fetch --tags
```

### 1. `git fetch origin`

- 做什麼：從 GitHub 下載新的歷史，存到 `origin/main`。
- 不做什麼：不改資料夾，也不改本機的 `main`。
- 為什麼：電腦要先拿到新歷史，下一步才能切換過去。

### 2. `git reset --hard origin/main`

- 做什麼：把本機的 `main` 直接改成指向新歷史，資料夾裡的檔案也改成和新歷史一樣。
- 為什麼不用 `git pull`：`pull` 會試著合併新舊歷史，舊的 commit 和那 2 個檔會留下。`reset --hard` 不合併，直接丟掉舊的，換成新的。
- 為什麼不是 `git reset --hard main`：本機的 `main` 還指向舊歷史，重設回原位置等於沒有改變。
- 代價：尚未 push 的修改都會不見，所以要先做「執行前」的確認。

### 3. `git tag -l | xargs git tag -d`

- 做什麼：`git tag -l` 列出本機所有 tag，`xargs git tag -d` 逐一刪除。
- 為什麼：本機的 5 個 tag 還指向舊的 commit。git 預設不會用遠端的同名 tag 覆蓋本機的 tag，所以要先刪掉。
- 影響：只刪本機的 tag，不影響 GitHub 上的 tag。

### 4. `git fetch --tags`

- 做什麼：從 GitHub 下載全部 tag。
- 為什麼：把指向新 commit 的 5 個 tag 下載回來。

## 執行後：確認已換成新歷史

```
git log --oneline -1
git tag -l
git log --all --oneline -- docs/tmp docs/學習筆記
```

正確的結果：

1. 第 1 行顯示 `2f5e831 feat(analyze): ...`。
2. 第 2 行列出 5 個 tag：`ch3-14-planners`、`ch3-15-tasks`、`ch3-17-clarify-over-specs`、`ch3-18-analyze`、`ch3-18-constitution`。
3. 第 3 行沒有輸出，表示歷史裡已經沒有那 2 個檔。

之後 `git pull` 和 `git push` 都只處理新歷史，那 2 個檔不會回來，舊的 commit 也不會被推回 GitHub。

另一個做法是刪掉舊資料夾，重新 `git clone`，結果相同。

## 其他注意事項

- 執行後，舊的 commit 還會在那台電腦的 git 資料裡留一段時間，但沒有分支或 tag 指向它們，不會被 push 出去。
- `docs/tmp/` 裡其他沒有進 git 的檔案（被 `.gitignore` 排除）不受影響。
- GitHub 上用舊 hash（例如 `891a5be`、`b0aaeae`）仍然打得開舊的 commit。要完全清除，需要到 https://support.github.com/request 選 **Sensitive data removal** 申請，repo 是 `AI-x-BDD/s-aixbdd-spec-kit`；組織 repo 可能要由組織管理員申請。
- 改寫後，`specs/skill-engineering/` 中 15、27、31 號紀錄寫到的 `9728b7b`、`ec338e1`、`bfba9e5` 已對不上新的 commit。這些只是紀錄文字，不影響 Skill 功能。
