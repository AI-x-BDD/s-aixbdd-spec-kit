# 後設反推：Artifact-First 第四步

來源：AI x BDD 第三章「【基因工程】改造屬於自己的 SDD 工作流：/specify」與後續幾個基因工程單元；「後設」和「反推」兩個詞的用法另外參考第一章「提案、約束和回饋」與第三章「/plan - 1」。

## 結論：不是兩個步驟，是同一個動作

「後設」和「反推」沒有先後之分。老師把兩個詞連在一起用，指的是**同一個動作**，交給 `skill-engineering` 一次完成。

證據是老師在不同單元裡，兩個詞的順序和組合都不固定：

- 第三章 /specify 單元：「它就直接幫你從這邊去**後設反推**你的 SOP 跟 rules」
- 同一個單元的 Prompt：「我需要你幫我去**後設**，去**反推**一下說⋯⋯」
- /artifact-to-skill-engineering 單元：「請它**後設出**一系列的推理流程跟規則」，同一段又說「第四步用老大哥來去**反推** SOP 跟 rules」
- /technical-research 單元：「再往下就是要**倒推後設**的那個 Skill」

如果是兩個有順序的步驟，老師不會一下說「後設反推」、一下說「倒推後設」。兩個詞是在描述同一件事的兩個面向。

## 兩個詞各自在講什麼

### 後設：講的是「層級」

後設（meta）是要 AI 往上跳一層：不要直接做那件事，而是去思考「做那件事的方法」，把它寫成可重用的東西。

這個詞第一章就出現了。老師在「提案、約束和回饋」單元裡請 AI「先後設我要求你做這個提案的行為」，整理成一份能在不同工作流重複使用的 Prompt File，後來還再往上一層，後設「你是如何後設的」，做出 Prompt Creator。

放到 /specify 的情境：不是叫 AI 產出一份 spec.md，而是叫它想清楚「產出 spec.md 的推理流程」，寫成 SOP 和 rules。

### 反推：講的是「方向」

反推是從結果往回推過程。第三章 /plan 單元有一句很直白的說法：「依照這個成果，你再去反推過程中大概需要經歷多少步驟。」

放到 /specify 的情境：起點是使用者輸入的 Prompt，終點是 spec.md。我們手上已經有終點（定稿的 example 和 template），所以從終點往回推，找出中間要經過哪些推理。

### 合起來

**後設反推 = 以產出物為終點，往回推出「產生它的推理流程」，並把這個流程寫成 Skill 的 SOP 和 rules。**

後設決定「推出來的東西是什麼」（可重用的流程，不是一次性的產出），反推決定「怎麼推」（從終點往回推）。

## 容易搞混的地方：流程裡有兩次「往回走」

會覺得有先後，很可能是把第三步和第四步混在一起了。Artifact-First 流程裡確實有兩個往回走的動作，而且有固定順序：

1. **第三步：倒抽 Template**
   - 從定稿的 `spec.example.md` 抽出 `spec.template.md`
   - 停留在**同一層**：都是產出物，只是從具體到抽象，去掉情境、留下骨架
   - 交給 `skill-form-template`
2. **第四步：後設反推 SOP 和 rules**
   - 從 template 加 example 推出 SKILL.md 的 SOP 和 rules
   - **跨了一層**：從產出物跨到產生它的流程
   - 交給 `skill-engineering`

所以順序是「先倒抽，再後設反推」。第三步一定要先做，因為第四步要拿 template 當目標，而 template 必須從定稿的 example 抽出來。

另外，第四步內部也有一個順序，就是老師 Prompt 裡說的「先抓 SOP，再抓 rules、scripts（如有需要），逐步增量」。這是產出的順序，不是後設和反推的順序。

## 後設反推要給 AI 哪些東西

老師的 Prompt 可以拆成三個輸入加兩個約束：

1. **終點**：template 和 example。「以那個檔案作為這個 Skill 它目標一定要能夠產出的 Artifact。」
2. **起點**：當初產出這份 spec 的原始 user prompt（Spec-Kit 官方的相簿範例，老師翻成繁中）。「今天使用者如果輸入了某個 Prompt，好比⋯⋯」
3. **要推的東西**：「要經過什麼樣子的推理流程、層層推理，最後才會超高可靠度地產出這樣子的 Artifact。」
4. **約束一，增量**：先抓 SOP，再視需要抓 rules、scripts。
5. **約束二，不要過度工程**：「盡可能避開過度工程，或是過度複雜化的 Skill 執行流程。」

最後加一句「請你先針對你的理解提案」。

起點和終點都要給。只給終點，AI 只能猜使用者會輸入什麼；起點和終點都有，AI 才推得出「從這樣的輸入，走到這樣的輸出，中間缺哪些推理」。老師說得很輕鬆：「那個 Prompt 找回來就行了。」

## 推出來的東西長什麼樣子

/specify 推出來的 SOP 有 5 步：

1. 對齊輸入與目標 Artifact（先讀 template，知道 spec.md 要長什麼樣子）
2. 收斂需求缺口，判斷要不要交給 clarify
3. 重建 spec 所需的語意骨架（切 User Story、把 FR／NFR 歸到 User Story 底下、跨故事的才留在全域）
4. 產出 spec Artifact
5. 自檢（對照 template 確認部位都到位）

另外有 3 個按需載入的 rules：使用者故事怎麼切、FR／NFR 怎麼歸類到 User Story、spec 完整性與一致性的自檢標準。

注意每一步都對得回產出物的某個部位：第 3 步對應的就是第二步改 example 時加進去的階層結構。這就是後設反推的價值，SOP 不是你憑經驗寫出來的，而是從產出物推出來的，所以每一步都有理由存在。

AI 在提案時有一句話老師特別稱讚：補齊 Artifact 需要的欄位時，「不是憑空腦補，而是根據前面已收斂出的故事需求做最小推導」。

## 執行時的小迴圈

後設反推不是丟出 Prompt 就結束，老師走了三輪：

1. **提案**：AI 先說出它的理解和規劃。
2. **劃界**：第一次提案被 `.spec-kit/` 裡的內容影響，AI 以為要改 Spec-Kit。老師補了一句「完全不要參考 Spec-Kit、不要做落差分析、從無到有增量迭代」，請它重新提案。
3. **落地**：讀完第二次提案、認同之後，才說「請你開始撰寫 Skill，一次完成整個計畫」。

## Skill 已經存在時的變化

/technical-research 單元裡，`artifact-to-skill-engineering` 跑到第四步時，Skill 已經先有一版了。這時候後設反推就變成「改良規劃」：以新的 template 為目標，推出現有 Skill 還缺哪些步驟和規則，老師看完規劃說「採納」就繼續。

方向一樣是從產出物往回推，只是起點從「空的 Skill」變成「現有的 Skill」。

## 一句話記住

先把產出物定稿（改 example → 倒抽 template），再請 `skill-engineering` 站到上一層，從產出物往回推出產生它的流程。後設是「往上一層」，反推是「往回推」，兩個是同一個動作。
