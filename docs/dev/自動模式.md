# 自動模式

自動模式是兩個可以開關的 hook。兩個開關預設都關；都關的時候，流程和手動流程完全相同。
它不修改任何 Skill、`clarify` 或 runbook 的步驟。

- 建立：2026-11-11（commit `e1d51ba`）
- 適用：Claude Code。`next` 只在 Herdr 的 pane 內有效。Codex 沒有接。

## 1. 兩個開關

| 開關 | 打開後的行為 |
|---|---|
| `clarify` | `clarify` 提問時不等你回答，直接採推薦選項，並把題目與採用的選項記進紀錄，標註「自動採推薦，非使用者決定」。 |
| `next` | 回覆結尾有「下一步提示詞」區塊時，Herdr 自動開新分頁、啟動新的 Claude Code、貼上提示詞。 |

## 2. 指令

```text
scripts/auto-mode.sh on clarify    # 打開 clarify
scripts/auto-mode.sh on next       # 打開 next
scripts/auto-mode.sh on all        # 兩個都開
scripts/auto-mode.sh off           # 全部關掉
scripts/auto-mode.sh off next      # 只關 next（也可以寫 clarify）
scripts/auto-mode.sh status        # 看目前狀態
scripts/auto-mode.sh help          # 印出用法
```

`on next` 與 `on all` 的選項：

| 選項 | 用途 | 不寫時 |
|---|---|---|
| `--steps N` | 最多自動接續幾步 | 12 |
| `--model M` | 新對話使用的模型 | 沿用上一個對話的模型 |
| `--effort E` | 新對話使用的 effort | 不指定 |

## 3. 什麼時候開

| 情況 | 做法 |
|---|---|
| 這一步做完，你要先看結果再決定下一步 | 不開 `next` |
| 連續好幾步，下一步照著走就好 | 開 `next` |
| 這幾步會遇到 `clarify` 提問，而你會照建議選 | 開 `clarify` |
| 這一步的 Skill 不提問（例如 `analyze`、`implement`） | `clarify` 開不開都一樣 |

## 4. 使用流程

情境：連續跑幾步，人不守在旁邊。

1. 在 Herdr 裡開一個新的 Claude Code，模型和平常一樣。
2. 打開開關：

   ```text
   scripts/auto-mode.sh on all
   ```

3. 貼上第一步的提示詞。之後可以離開。
4. 每一步做完，Herdr 會開一個新分頁執行下一步。每個分頁是一步的完整對話。
5. 回來後關掉開關：

   ```text
   scripts/auto-mode.sh off
   ```

## 5. 它什麼時候會自己停

1. 回覆結尾沒有下一步提示詞區塊。例如那一步失敗，或 agent 在等你決定。
2. 達到步數上限。要繼續時，重新執行 `scripts/auto-mode.sh on next`。
3. 你執行 `off`。
4. agent 卡在確認畫面。Herdr 會顯示 `blocked`，你回答後才繼續。

## 6. 注意事項

1. 開關只對新開的 Claude Code 對話有效。開關打開前就在跑的對話，要看它啟動時有沒有載入這兩個 hook。
2. `clarify` 開關不涵蓋覆寫既有產出、刪除檔案、push、打 tag 的確認。遇到這些，流程會停下來等你。
3. `clarify` 開關是用提示詞約束模型，不是硬性保證。
4. 新對話沿用上一個對話的模型與權限模式。要固定模型時用 `--model`。A/B 比較這類要求模型相同的工作，要明確指定。
5. 自動採用的答案不是你的決定。迭代紀錄要照實寫，並記下那一段用了自動模式。
6. 流程沒有接下去時，先看紀錄檔 `.auto/next.log`。

## 8. 測試紀錄（2026-11-11）

1. `next`：在 Herdr 以 Haiku 實跑兩步的假流程。第一步結束後，hook 自動開新分頁、啟動 Claude Code、貼上提示詞；第二步回覆後停止。通過。
2. 提示詞擷取：測了 5 種情況，包含區塊內有巢狀程式碼、區塊後面還有文字（這種不接續）。通過。
3. `clarify`：只測了 hook 的輸出，模型行為沒有實跑。依據是紀錄 47 驗收 S1 用同樣的寫法有照做。
