# 精密實驗設備借用中心（設備預約審核與現場借還管理系統）

本目錄（`apps/equipment-loan/`）為「設備借用與預約審核、現場領取歸還管理系統」的原始碼與跨前後端測試入口。

迭代 4 新增「預約改期申請」：成員可把「已核准／有效」且原時段尚未開始的預約，改到同一台設備當日起算 7 天內的另一個固定時段。

- 免審核設備：新時段仍未被占用時立即改期，預約編號與狀態不變，原時段立即釋出。
- 需人工審核設備：建立「改期審核中」的改期申請；管理員核准前原預約照常有效，新時段不替成員保留。
- 改期申請有 5 種狀態：改期審核中、改期成功、改期被駁回、改期已撤回、改期已失效。
- 成員可在「我的預約」查看改期紀錄、撤回審核中的申請；管理員在「審核與借用管理」的「改期申請」分頁核准或駁回。
- 原時段或新時段開始、原預約被取消或登記領取時，審核中的申請自動變成「改期已失效」（查詢前惰性失效，不需要排程器）。

## 1. 環境需求

- Node.js 24 LTS 以上
- Docker 與 Docker Compose（用於啟動 PostgreSQL 18 容器）

## 2. 快速啟動步驟

在 `apps/equipment-loan/` 目錄下依序執行：

```bash
# 1. 安裝頂層、後端與前端依賴
npm install
npm --prefix backend install
npm --prefix frontend install

# 2. 建立後端環境變數檔（若尚未建立）
cp -n backend/.env.example backend/.env || true

# 3. 啟動 PostgreSQL 18 容器
docker compose up -d --wait

# 4. 套用無損 Prisma 資料庫遷移並載入預建展示資料（demo seed：預約 6 態與改期申請 5 態）
npm run db:migrate
npm run db:seed

# 5. 啟動後端（http://localhost:3000/api）與前端（http://localhost:5173）
npm --prefix backend run dev
npm --prefix frontend run dev
```

### 2.1 從迭代 3 升級：增量資料庫遷移

已經跑過前三次迭代的資料庫，只要在 `apps/equipment-loan/` 執行：

```bash
npm run db:migrate
```

這個指令套用 `backend/prisma/migrations/20261109154235_reschedule_requests/`，新增 `reschedule_requests` 資料表、改期申請狀態與失效原因 Enum，以及「每筆預約最多一筆改期審核中申請」的部分唯一索引。既有的使用者、設備、時段與預約資料不會被刪除或改寫。

### 3.4 預建改期申請 5 態範例（迭代 4 擴充）

下列「明天」、「後天」等日期都以執行 `npm run db:seed` 當天為準。

- **改期審核中 (`pending_approval`)**：
  - 林雅婷 `RV-20261108-04`（`EQ-101` 明天上午）申請改到後天晚間：新時段未被占用，管理員可以核准。林雅婷在「設備預約」看到後天晚間 `EQ-101` 標示「本人改期審核中」，陳冠廷看到「可預約」。
  - 陳冠廷 `RV-20261108-11`（`EQ-102` 四天後上午）申請改到三天後下午：新時段已被林雅婷的 `RV-20261109-12` 占用，管理員核准會被拒（`409 RESCHEDULE_SLOT_CONFLICT`），可改為駁回。
  - 林雅婷 `RV-20261108-06`（`EQ-103` 今天晚間）申請改到明天晚間：可示範取消或登記領取原預約時，申請一併變成「改期已失效」。
- **改期成功 (`approved`)**：林雅婷 `RV-20261108-08`（`EQ-103` 免審核）已從三天後上午即時改期到三天後下午，沒有審核管理員。
- **改期被駁回 (`rejected`)**：陳冠廷 `RV-20261108-07`（`EQ-101` 明天下午）申請改到後天上午，由吳承翰駁回並附駁回原因。
- **改期已撤回 (`withdrawn`)**：林雅婷 `RV-20261109-12`（`EQ-102` 三天後下午）申請改到四天後晚間，之後由本人撤回。
- **改期已失效 (`expired`)**：
  - 林雅婷 `RV-20261108-03`（`EQ-101` 今天下午）申請改到後天下午，原時段開始時自動失效（失效原因「原時段開始」）。
  - 林雅婷 `RV-20261107-06`（`EQ-103` 明天上午）申請改到三天後晚間，原預約取消時一併失效（失效原因「原預約已取消」）。
- **可即時改期 (`confirmed`)**：林雅婷 `RV-20261108-05`（`EQ-104` 免審核，後天上午）可以立即改到後天下午；改到後天晚間會被拒，因為陳冠廷的 `RV-20261109-13` 已占用該時段。

## 4. 靜態檢查與自動化測試

在 `apps/equipment-loan/` 目錄下執行：

```bash

npm run check

# 後端單元與整合測試（Vitest 5 + Supertest 7 + 真實 PostgreSQL 18）
npm run test:backend

# 前端單元測試（Vitest 5）
npm run test:frontend

# 跨前後端端對端測試（Playwright 1.65）
npm run test:e2e
```

迭代 4 新增的改期測試可以單獨執行：

```bash
# 後端：時段開始時間換算、7 天範圍與可改期條件單元測試
npm --prefix backend run test -- tests/unit/reschedule.test.ts

# 後端：改期成功與拒絕、並發占用、自動失效、角色權限整合測試（真實 PostgreSQL，測試結束後重設為 demo seed）
npm --prefix backend run test -- tests/integration/reschedule.test.ts

# E2E：成員與管理員雙視窗的即時改期、改期審核、核准衝突與撤回
npx playwright test e2e/reschedule.spec.ts
```

> 注意：前三次迭代的回歸測試 `backend/tests/integration/api.test.ts` 與 `e2e/equipment-loan.spec.ts` 會登記領取「今天晚間」的預約，只有在 `Asia/Taipei` 18:00–21:00 之間執行才會全部通過。迭代 4 新增的改期測試不受執行時刻影響，但請避開午夜換日時執行。E2E 測試會自動執行 `npm run db:seed`，並在 3000 埠（後端）與 5183 埠（前端）啟動伺服器；這兩個埠已有伺服器時會直接沿用。

## 5. 雙視窗展示改期流程

先執行 `npm run db:seed`，再依第 2 節啟動後端與前端，打開 `http://localhost:5173`。用一般視窗登入成員、無痕視窗登入另一位成員或管理員，對照操作：

1. **免審核即時改期**：林雅婷到「我的預約」，在 `RV-20261108-05` 按「申請改期」，在對話框選後天下午並送出。畫面顯示改期成功，預約編號不變。陳冠廷在「設備預約」選後天，看到 `EQ-104` 上午變成「可預約」。
2. **新時段被占用時拒絕**：林雅婷再對 `RV-20261108-05` 開啟對話框，後天晚間標示「已被預約」，點選時顯示原因，原預約不變。
3. **需人工審核改期**：陳冠廷到「我的預約」，對 `RV-20261108-07`（`EQ-101` 明天下午）申請改到後天上午。畫面顯示「改期審核中」，原預約仍為明天下午。陳冠廷在「設備預約」看到後天上午標示「本人改期審核中」，林雅婷看到同一時段「可預約」。
4. **管理員核准與核准衝突**：吳承翰到「審核與借用管理」，待審清單預設顯示「改期申請」分頁。核准陳冠廷 `RV-20261108-11` 的申請時，頁頂顯示新時段已被 `RV-20261109-12` 占用，申請維持審核中；改按「駁回」即可結案。核准第 3 步的申請後，陳冠廷的預約改到後天上午，明天下午釋出。
5. **成員撤回**：林雅婷到「我的預約」，在 `RV-20261108-04` 的改期紀錄按「撤回」並確認。申請變成「改期已撤回」，原預約維持明天上午，管理員待審清單不再顯示這筆申請。
6. **自動失效**：在今天 18:00 前，林雅婷取消 `RV-20261108-06`，或吳承翰登記領取 `RV-20261108-06`，這筆預約的改期審核中申請會一併變成「改期已失效」，管理員無法再核准。今天 18:00 一到，原時段開始，這筆申請也會自動變成「改期已失效」。
7. **待審預約申請**：前三次迭代的待審預約申請（例如 `RV-20261109-08`、`RV-20261109-09`）改放在待審清單的「預約申請」分頁。
