# Feature Specification: 線上 PVP 1A2B 猜數字對戰平台 (Online PVP 1A2B)

**Feature Branch**: `001-online-pvp-1a2b`

**Created**: 2026-10-22

**Status**: Draft

**Input**: User description: "接下來我想要做一個全線上的 PVP 的一個 1A2B 猜數字的遊戲 所以它是一個線上平臺 所以一定就是玩家在這個平臺上開一個房間 四個號碼 開個房間 另外一個玩家呢 用四個號碼只要比對到了 就可以加入 沒有比對到就是開新的房間 準備好之後房主開房然後開始 1A2B 兩個人互相猜對方的答案"

## Clarifications

### Session 2026-10-22

- Q: 房間的四個號碼，在系統裡扮演什麼角色? (FR-002, FR-009) → A: 四碼只是「房間配對碼」，進房後雙方各自另外設定秘密答案。
- Q: 對戰時的出手方式和勝負判定，第一版要採哪一種? (FR-012, FR-014) → A: 輪流制，房主先手，先猜出 4A 者獲勝。
- Q: 玩家在平台上的身分，第一版要怎麼處理? (FR-001) → A: 免註冊，進站輸入暱稱即可，不保留戰績。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 以四碼配對碼開房或加入房間 (Priority: P1)

玩家以暱稱進入平台後，輸入一組四碼配對碼：若已有使用相同配對碼、正在等待對手的房間，就加入該房間成為對手；沒有符合的房間，就開一間新房間並成為房主，等待對手加入。

**Why this priority**: 配對與房間是整個線上對戰的入口；沒有兩位玩家進到同一間房，後續的準備與猜數字都無從進行，因此是最先要被證明的價值。

**Independent Test**: 以兩個互不相干的瀏覽器工作階段各輸入暱稱，先後輸入相同配對碼；驗證第一位成為房主並等待，第二位進入同一房間，雙方都看到彼此暱稱。再以第三個工作階段輸入同一配對碼，驗證其被分配到新的房間。

**Acceptance Scenarios**:

1. **Given** 玩家 A 已輸入暱稱進站且沒有符合的等待中房間，**When** A 輸入配對碼 `1234`，**Then** 系統建立新房間，A 成為房主並看到「等待對手加入」的狀態。
2. **Given** 已存在配對碼為 `1234`、只有房主一人的等待中房間，**When** 玩家 B 輸入配對碼 `1234`，**Then** B 進入該房間，且雙方畫面都顯示房主與對手的暱稱。
3. **Given** 配對碼為 `1234` 的房間已有兩位玩家，**When** 玩家 C 輸入配對碼 `1234`，**Then** 系統為 C 建立新房間，C 成為該新房間的房主。
4. **Given** 玩家位於配對碼輸入畫面，**When** 輸入 `12a` 或少於四位的內容並送出，**Then** 系統以繁體中文提示配對碼必須為四位數字，且不建立也不加入任何房間。
5. **Given** 房主在等待對手的房間中，**When** 房主離開房間，**Then** 該房間關閉，之後輸入同一配對碼的玩家會建立新房間。

**Functional Requirements**:

- **FR-001**: 系統必須 (MUST) 允許玩家只輸入暱稱即可進站使用，不得要求註冊或登入，也不得保存跨連線的戰績；暱稱為空時，系統必須拒絕進站並提示輸入暱稱。
- **FR-002**: 系統必須 (MUST) 在玩家輸入四碼配對碼後，若存在配對碼相同且只有一位玩家的等待中房間，就讓該玩家加入該房間成為對手。
- **FR-003**: 系統必須 (MUST) 在玩家輸入四碼配對碼後，若沒有符合的等待中房間，就自動建立新房間並讓該玩家成為房主。
- **FR-004**: 系統必須 (MUST) 限制每間房間最多兩位玩家；配對碼相同但房間已滿或對局已開始時，必須視為沒有符合的房間，為該玩家建立新房間。
- **FR-005**: 系統必須 (MUST) 只接受恰好四位、每位皆為 `0` 至 `9` 的配對碼，格式不符時以繁體中文顯示錯誤提示，且不得建立或加入房間。
- **FR-006**: 系統必須 (MUST) 在房間畫面顯示已在房內的玩家暱稱，並標示哪一位是房主。
- **FR-007**: 系統必須 (MUST) 在房主於對局開始前離開房間時關閉該房間，並釋出其配對碼供之後的玩家重新使用。

**Non-Functional Requirements**:

- **NFR-001**: 玩家送出配對碼後，到看見房間畫面（加入或新建）的時間必須 (MUST) 在一般網路條件下低於 2 秒。

### User Story 2 - 房主開始遊戲並雙方設定秘密答案 (Priority: P2)

房間內湊滿兩位玩家後，房主可以按下開始；雙方各自設定一組只有自己知道的四位秘密答案，兩人都設定完成後，進入互猜階段。

**Why this priority**: 這一步建立在雙方已進入同一房間之上，並產生對戰所需的兩組秘密答案；沒有它，下一階段的互猜無法進行，但它又必須在房間配對成立之後才有意義。

**Independent Test**: 在已湊滿兩人的房間中，驗證只有房主能開始遊戲；雙方各自輸入合法的秘密答案後，確認畫面進入猜測階段，且任一方的畫面上都看不到對方的答案。

**Acceptance Scenarios**:

1. **Given** 房間內只有房主一人，**When** 房主嘗試開始遊戲，**Then** 系統不啟動遊戲，並以繁體中文提示需等待對手加入。
2. **Given** 房間內有房主與對手兩位玩家，**When** 非房主玩家檢視房間畫面，**Then** 畫面上沒有可操作的「開始遊戲」功能。
3. **Given** 房間內有兩位玩家，**When** 房主按下開始遊戲，**Then** 雙方畫面都進入「設定秘密答案」階段。
4. **Given** 玩家位於設定秘密答案階段，**When** 輸入含重複數字的答案（例如 `1123`）並送出，**Then** 系統以繁體中文提示答案必須是四個不重複的數字，並不接受該答案。
5. **Given** 玩家 A 已完成設定、玩家 B 尚未完成，**When** A 檢視自己的畫面，**Then** A 看到「等待對手設定答案」的狀態，且尚未進入猜測階段。
6. **Given** 雙方都已完成設定秘密答案，**When** 最後一位玩家確認答案，**Then** 雙方畫面進入猜測階段，並由房主先手。
7. **Given** 玩家 A 與 B 正在設定秘密答案，**When** B 離開房間，**Then** A 看到對局無法繼續的提示並回到入口畫面，且不判定勝負。

**Functional Requirements**:

- **FR-008**: 系統必須 (MUST) 只允許房主在房間內已有兩位玩家時開始遊戲；房間未滿兩人，或操作者不是房主時，系統不得啟動遊戲。
- **FR-009**: 系統必須 (MUST) 在遊戲開始後，讓兩位玩家各自設定一組只有自己知道的秘密答案；配對碼不得被當成任何一方的秘密答案。
- **FR-010**: 系統必須 (MUST) 在雙方都完成秘密答案設定後，才進入猜測階段，並指定房主為先手。
- **FR-018**: 系統必須 (MUST) 在設定秘密答案階段有一方離開或斷線時，通知另一方對局無法繼續並讓其回到入口畫面，且不判定勝負。

**Non-Functional Requirements**:

- **NFR-002**: 在對局結束之前，任一玩家的秘密答案必須 (MUST) 不得以任何畫面或介面被對手取得。

### User Story 3 - 輪流猜對方答案直到分出勝負 (Priority: P3)

猜測階段中，兩位玩家輪流猜對方的四位秘密答案，每次猜測後系統回報幾 A 幾 B；先猜出 4A 的玩家獲勝，對局結束並揭曉雙方答案。

**Why this priority**: 這是玩法本身的完整體驗，但它依賴已配對成功的房間與雙方已設定好的答案，所以排在前兩個故事之後。

**Independent Test**: 以兩位玩家進入猜測階段，輪流提交猜測；驗證 A、B 回饋與標準 1A2B 規則一致，輪次交替，其中一方猜出 4A 後對局結束並宣告勝者。

**Acceptance Scenarios**:

1. **Given** 輪到玩家 A 且玩家 B 的秘密答案為 `1234`，**When** A 猜 `1243`，**Then** 系統回報 `2A2B`。
2. **Given** 輪到玩家 A，**When** A 提交合法猜測，**Then** 輪次交給 B，且雙方畫面都顯示該次猜測與其 A／B 結果。
3. **Given** 目前輪到玩家 A，**When** 玩家 B 嘗試提交猜測，**Then** 系統不接受，並提示尚未輪到 B。
4. **Given** 輪到玩家 A，**When** A 提交含重複數字的猜測，**Then** 系統以繁體中文提示猜測必須是四個不重複的數字，且仍輪到 A。
5. **Given** 輪到玩家 A，**When** A 猜出 `4A`，**Then** 對局結束，雙方畫面宣告 A 獲勝並揭曉雙方的秘密答案。
6. **Given** 雙方正處於猜測階段，**When** 其中一位玩家斷線或離開房間，**Then** 另一位玩家被判獲勝，對局結束。

**Functional Requirements**:

- **FR-011**: 系統必須 (MUST) 在猜測階段，對玩家提交的每一個合法猜測，依對手的秘密答案回報幾 A（數字與位置皆正確）幾 B（數字正確但位置錯誤）。
- **FR-012**: 系統必須 (MUST) 讓兩位玩家依輪流制進行猜測，房主先手，只有輪到的玩家可以提交猜測。
- **FR-013**: 系統必須 (MUST) 在雙方畫面上顯示本場所有猜測紀錄及其 A／B 結果。
- **FR-014**: 系統必須 (MUST) 在任一玩家猜出 `4A` 時立即結束對局，宣告該玩家獲勝，並向雙方揭曉雙方的秘密答案。
- **FR-015**: 系統必須 (MUST) 在猜測階段，一方斷線或離開房間時，立即判定另一方獲勝並結束對局。
- **FR-016**: 系統必須 (MUST) 在對局結束後，讓雙方都能離開房間回到入口畫面，重新輸入配對碼開始新的房間。

**Non-Functional Requirements**:

- **NFR-003**: 一位玩家提交合法猜測後，對手畫面更新該次猜測與輪次的時間，在 95% 以上的情況下必須 (MUST) 低於 1 秒。

---

### Edge Cases

- **同時輸入同一配對碼**：兩位玩家在幾乎同一時間輸入相同的配對碼，且當時沒有等待中房間時，先被系統處理的玩家成為房主，另一位加入該房間，不得各自建立一間房間。
- **配對碼被占用**：配對碼 `1234` 的房間已滿或已開始對局時，其他玩家輸入 `1234` 會進入新房間，不得被拒絕進站。
- **重複猜同一組數字**：玩家重複猜過的合法數字時，系統照常回報結果並記入猜測紀錄，不另外限制。
- **等待中房主離開**：房主在對手加入前離開，房間關閉，配對碼釋出供重新使用。
- **秘密答案階段離開**：雙方設定答案階段有一方離開時，系統通知另一方對局無法繼續並讓其回到入口，不判定勝負。

## Requirements *(mandatory)*

> 使用者故事專屬的 FR／NFR 直接列在該故事底下；本節只放無法歸屬單一使用者故事，或明確跨越多個使用者故事的全域需求。

### Global Requirements

#### Functional Requirements

- **FR-017**: 系統必須 (MUST) 要求秘密答案與每次猜測都是恰好四位、每位皆為 `0` 至 `9`、且四位互不重複的數字，可以 `0` 開頭；不符時以繁體中文提示並不接受。

#### Non-Functional Requirements

- **NFR-004**: 所有使用者介面文字、狀態提示與錯誤提示必須 (MUST) 使用自然且清晰的臺灣繁體中文呈現，且錯誤提示必須讓使用者看得懂問題所在。

### Key Entities *(include if feature involves data)*

- **玩家 (Player)**：代表一位進站的使用者。關鍵屬性包含：暱稱、目前所在的房間、在房間中的角色（房主或對手）。身分只在本次連線期間有效，不跨連線保存。
- **房間 (Room)**：代表一場對戰的容器。關鍵屬性包含：四碼配對碼、房內玩家（最多兩位）、房主、房間狀態（等待對手、設定答案、對戰中、已結束）。
- **秘密答案 (Secret Answer)**：代表玩家設定、供對手猜測的四位不重複數字。關鍵屬性包含：所屬玩家、四位數字；在對局結束前不對對手公開。
- **猜測紀錄 (Guess)**：代表一次猜測。關鍵屬性包含：提交的玩家、猜測的四位數字、A 與 B 的數量、提交順序。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 兩位新玩家從進站到進入同一間房間，90% 以上能在 30 秒內完成。
- **SC-002**: 以 50 組隨機配對碼測試，「有符合的等待中房間必定進入同房、沒有符合必定開新房」的正確率達 100%。
- **SC-003**: 一位玩家提交猜測後，對手畫面在 1 秒內顯示更新的比率達 95% 以上。
- **SC-004**: 在對局結束之前，對手透過任何畫面取得秘密答案的次數為 0。
- **SC-005**: 以 100 組不同的答案與猜測組合測試，A／B 回報結果與標準 1A2B 規則的一致率達 100%。

## Assumptions

- **數字規則採經典 1A2B**：使用者未指定數字規則，本次採秘密答案與猜測皆為四位不重複的數字（FR-017）；配對碼（FR-005）則允許重複數字，因為它只用來配對房間。
- **暱稱不要求唯一**：不同玩家可使用相同暱稱，系統只靠本次連線區分玩家；暱稱長度上限於技術規劃階段決定。
- **不支援斷線重連**：玩家斷線或離開後視同離開對局，第一版不提供重新連回同一場對局的功能（見 FR-015）。
- **不限制單次出手時間**：第一版不設定每次設定答案或猜測的時間上限，玩家可自行決定思考時間。
- **不支援觀戰與再來一局**：每間房間只容納兩位玩家，不提供觀戰；對局結束後房間關閉，想再玩需重新輸入配對碼開房（見 FR-016）。
- **配對碼被占用視為未符合**：使用者只說「沒有比對到就是開新房間」，本次將「配對碼相同但房間已滿或已開始」解讀為沒有符合（見 FR-004）。
