## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `implement`／`rules/自主決策-格式規範.md`／Rule 2 第 2 條與 Rule 1 權威表，對照 `SKILL.md` Phase 2 步驟 11 | 衝突 | 觀察：步驟 11 規定「任務要求和『憲法檢查清單』的必須／不得規則無法同時滿足時……和憲法衝突的任務記入『受阻任務』」。觀察：Rule 2 第 2 條規定「只有環境限制（外部服務無法啟動、套件或映像無法下載、缺少權限、憑證或硬體）導致任務無法完成時，才可以把任務記為受阻」，憲法衝突不在其中。觀察：Rule 1 權威表只有 spec、介面規格、research／techstack、tasks.md 四層，沒有憲法，也沒有規定憲法衝突要走受阻。觀察：紀錄 32 C8 寫「受阻任務的處理方式由既有 `rules/自主決策-格式規範.md` 負責」，但紀錄 32 沒有修改這個 RuleFile。推論：測試 session 同時載入兩邊（P2-3、P2-7 觀察），依 Rule 2 不能把非環境原因記為受阻，於是依 Rule 1 的「矛盾時依權威自行決策並記錄後繼續」處理，寫出「憲法優先於任務描述」的決策並打勾（P2-9 觀察）。受阻分支沒有被使用，報告只能把衝突放進「憲法偏離」（E2 的落差同屬此根因） | 假設 Rule 2 把「任務要求和憲法必須／不得規則無法同時滿足」列為可記受阻的原因，並禁止以刪改任務要求的方式完成：P2-9 辨識出衝突後，依決策檢查清單記為受阻；P2-11 略過打勾；P2-13 輸出受阻；P3-2 列入「因憲法衝突而受阻的任務」，「憲法偏離」為空。E1、E2 滿足；連帶受阻依 Rule 2 原有條文處理，E3 滿足；其餘流程不變，E4、E5 不受影響 |
