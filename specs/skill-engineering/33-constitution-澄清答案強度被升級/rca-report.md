# 根因報告：constitution－澄清答案強度被升級

- 紀錄目錄：`specs/skill-engineering/33-constitution-澄清答案強度被升級/`
- 問題證據：`user-verify-skill` 整理的問題證據（本次對話上下文）；測試 session 對話紀錄 `~/.claude/projects/-private-tmp-…-scratchpad-verify-constitution-85/6a7372fb-572a-445d-9f8b-9850f0ebe5f9.jsonl`；產出檔 `verify-constitution-85/.agents/constitution/skills/data-plan/data-model.md`；`constitution` 的 `SKILL.md` 與 `rules/憲法規則-格式規範.md`；31 號藍圖 S6、32 號藍圖 S7 紀錄。

## 1. 使用者回報的問題

使用者要求生命週期欄位與軟刪除。`clarify` 第 2 題問「是否要求另外記錄建立人（`created_by`）」，使用者選「不要求建立人，只記修改人」；第 3 題問刪除者記在哪裡，使用者選「寫入 `updated_by`」。產出的規則卻寫成「資料表不得有 `created_by` 欄位」與「資料模型不得設計 `deleted_by` 欄位」，把「不要求」升級成「禁止」。這兩條「不得」會讓 `data-plan` 在 spec 需要建立人時判定憲法衝突，造成假衝突。

## 2. 驗收條件

| 編號 | 驗收條件 | 來源 | 適用範圍 | 驗收情境 |

| E1 | 使用者在需求或澄清中表示「不要求」、「不需要」某項內容時，規則不寫該項的要求，也不寫禁止該項的「不得」條文 | 本次 | 通用 | S1 |
| E2 | 使用者明確要求禁止某項內容時，規則以「不得」寫出該禁止 | 推定：E1 只限制「不要求」被升級；若改寫時連帶刪掉使用者真正要求的禁止，會變成另一種偏離 | 通用 | S1 |

## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `constitution`／`rules/憲法規則-格式規範.md`／Rule 3 | 缺失 | 觀察：Rule 3 只規定「規則只能包含使用者提出的要求與『澄清結果』」，沒有規定澄清結果怎麼換成強度用詞；Rule 2 只定義用詞，沒有規定用詞要對應使用者的原意。推論：執行者把「不要求 X」視為澄清結果，換成「不得 X」也不違反現有文字（依據 P2-6、P2-7 的觀察） | 假設 Rule 3 規定「『不要求』只代表不把該項寫成要求，不得寫成『不得』；只有使用者明確要求禁止時才寫『不得』」：P2-6 不會寫出第 8、44 行，P2-7 會攔下；E1 可滿足，E2 由同一條保留，E3 不受影響 |

## 6. 被排除的假設

| 假設 | 缺陷類型 | 排除依據 |
| ---- | -------- | -------- |
| 規則檢查清單沒有在寫入前載入 | 未載入 | 觀察：對話紀錄第 2 個工具呼叫已 `cat` `rules/*.md`，P2-4 載入在 P2-6 之前 |
