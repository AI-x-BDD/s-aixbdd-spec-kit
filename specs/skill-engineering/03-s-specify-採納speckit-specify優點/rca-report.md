# 根因報告：s-specify－採納 speckit-specify 優點

- 紀錄目錄：`specs/skill-engineering/03-s-specify-採納speckit-specify優點/`
- 問題證據：本次對話上下文（以 `/s-specify` 執行 1A2B 需求的完整過程與回報訊息；使用者比較 `.spec-kit/agents-skills/speckit-specify` 與 `.agents/skills/s-specify` 後選擇「依建議」採納 1～5 項）；產出檔 `specs/001-online-pvp-1a2b/spec.md`；Skill 檔案 `.agents/skills/s-specify/SKILL.md` 及其 3 份 RuleFile 與樣板組

## 1. 使用者回報的問題

使用者以 `.agents/skills/s-specify` 為主力，比較 `speckit-specify` 後，要求採納 5 項 `s-specify` 缺少的能力：

1. 輸入異常時明確中止：功能描述為空，或澄清後仍無法切出使用者故事時，不硬產 spec.md。
2. 自檢最多 3 輪，仍未通過時回報使用者。
3. 每條 FR 都要有對應的驗收情境。
4. 範圍要有明確邊界，寫出這次不做什麼。
5. 回報時建議下一步。

## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `s-specify`／`SKILL.md`／Phase 1 步驟 1～3、Phase 2 步驟 2 | 流程缺陷 | 觀察：Phase 1 沒有空輸入時的中止閘門；Phase 2 步驟 2 與完成條件沒有「切不出故事」的出口。推論：任何輸入都會一路走到 P3-3 寫檔（依據 P1-1、P2-2 的觀察） | 假設 P1 有空輸入中止閘門、P2 有切不出故事時的停止出口：S1 在 P1 中止且不建立目錄，S2 在 P2 停止並說明原因，E1、E2 可滿足；E7～E10 只在正常路徑生效，不受影響 |
| R2 | `s-specify`／`SKILL.md`／Phase 2 步驟 5、Phase 3 步驟 4 | 流程缺陷 | 觀察：兩個 `CHECK` 只寫「未通過時修正」，沒有輪數上限與未通過時的回報。推論：修不好時可能無限修正，或默默交出不合格的 spec（依據該兩步的文字） | 假設兩個 `CHECK` 寫明最多 3 輪、第 3 輪仍未過則記錄未通過項並在 P3-5 回報：演練時 E3 可滿足，E6 的分支也有依據 |

## 6. 被排除的假設

| 假設 | 缺陷類型 | 排除依據 |
| ---- | -------- | -------- |
| H1：空輸入處理已由 clarify 涵蓋 | 交接缺陷 | 觀察：clarify Phase 1 步驟 1 讀取需求後直接盤點缺口，沒有空輸入的中止規則；且 E1 要求不委派 clarify |
