## 2. To-Be SOP 與交接範例

### Phase 1 -- 選路

1. 辨識是否為單節課程素材轉文章。若是，選 `course-article`；若是單問觀念、只整理私人筆記或要求章級整合，回報第一版尚無這條路徑，不代辦。
2. 核對來源是否可讀。使用者給了課名但未給路徑時，先在相鄰的私有課程 repo 找。只有找不到或有多份候選時，才問「請給我這一節的逐字稿路徑，或貼上逐字稿。」
3. 核對輸出路徑。來源已齊但沒有輸出位置時，只問「文章和筆記要存在哪個私有資料夾？」已提供則沿用。發現輸出目錄已有成品且未授權覆寫時，請使用者給新目錄或確認覆寫。兩項都齊才交接。

完成條件：已選 `course-article`，且來源與私人輸出位置已確認；否則停在缺項或無路徑的回報。

### Phase 2 -- 交接

載入同一工作樹的 `course-article/SKILL.md`，並依既有 SOP 執行。不要求另一個代理或新的全域安裝。以完整路徑交接，不在正式 Skill 寫死此範例的路徑。

〈Intro to AI Agents〉範例（假設使用者已指定新目錄 `steve-v1`；本輪已查它尚未被占用）：

> `course-article`，請把〈Intro to AI Agents〉寫成一篇能獨立閱讀的繁體中文入門文章。來源為私有 repo `lesson-preparation-perspective` 的 `materials/courses/ai-agents-fundamentals-v2/02-agent-basics/01-intro-to-ai-agents/transcript.md`。請把 `article.md` 和 `notes.md` 寫到同一私有 repo 的 `articles/intro-to-ai-agents/steve-v1/`；現有 `course-article-s1/` 保留。完成後請回傳兩個完整路徑、最新筆記的引句檢查結果、正文的來源終檢結果、篇幅結果，以及關鍵字的查證狀態。這一節要讓讀者看懂誰決定下一步，以及 Agent 收到工具結果後怎麼判斷是否繼續。只使用課程內容，寫作、篇幅選擇與潤稿由你依 SOP 處理。受阻時回報哪一步卡住及目前留下的檔案。

完成條件：拿到本次產物與檢查結果，或明確的受阻原因。

### Phase 3 -- 收件

1. 查看指定輸出位置的 `article.md` 和 `notes.md`，避免把先前留存的檔案算成本次結果。依目前的逐字稿及 `notes.md` 執行既有引句檢查腳本，比對退出碼；正文以對應最新稿件的來源終檢結果為準。檢查結果缺漏時，請 `course-article` 補查；Steve 不複製正文核對規則。篇幅按子 Skill 現有規則處理，包括明確回報「未實測」。
2. 兩檔和必要結果齊全且通過，交付路徑。關鍵字有查證狀態即可；未查證時回報「文章與筆記可交付；這些詞目前是候選，搜尋價值仍待查證。」
3. 若引句檢查失敗，先退回同一 Skill，例如：「這次的 `notes.md` 有一段引文與原稿不符。請按檢查結果指出的位置，逐字修正該段，再重跑引句檢查；保留已通過的正文。如果正文尚未產生，待引句通過後接續原本的寫文流程。回傳最新路徑與檢查結果。」重驗通過才交付；若一次退回後仍受阻，回報原因。使用者確實需要補資料時，只問那項；工具失敗就回報工具問題，不請使用者重交已讀到的逐字稿。

完成條件：已交付、已退回等待查核，或已回報受阻與必要輸入；不把草稿回報成正式稿。
