## 1. 使用者回報的問題

故事規則 Rule 2 同時要求「P1 代表最先需要被證明的核心價值」和「依賴其他故事的排在後面」。兩者衝突時，依賴會勝出。以 1A2B 線上對戰為例，「猜對方的答案」是核心玩法，卻因為要先配對進房、先設定答案，只能排在 P3。

你參考課程內容後同意的方向：優先級只看使用者價值，依賴不影響排序；課程中講師說 Priority 是「這個功能對使用者是不是很重要」（〈速成主流工具，用 Spec-kit 來做 SDD - 憲法& Specify〉約 15:06），依賴則在 tasks 階段由「阻塞的前置條件」處理（〈/tasks & /implement〉約 9:27～12:03）。

## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `s-specify`／故事規則 Rule 2（標題與第 1 條、Good Example、Bad Example）；範例三個故事的 `Why this priority` 示範了同樣的排序方式 | 衝突 | 觀察：Rule 2 第 1 條（第 33 行）在同一條裡要求「`P1` 必須代表最先需要被證明的核心價值」與「建立在其他故事成果之上的故事，必須排在該故事之後」；標題（第 31 行）寫「依使用者價值與交付順序排列」。Good Example 的說明（第 39 行）是「理由都指出依賴與價值」，P1 的理由是「沒有相簿與分組，預覽與拖放都無從運作」（第 43 行）；範例 US1 的理由也寫「後續的預覽與拖放排序便無從運作」（範例第 27 行）。推論：核心價值與依賴指向不同故事時，兩個要求互相矛盾；規則與範例都示範用依賴當排序理由，AI 因此讓依賴勝出（依據上述條文與 1A2B 產出第 25、57、88 行） | 假設 Rule 2 只依使用者價值排序，依賴只在價值理由之後寫成「實作前提：……；不影響本故事優先級」，Good Example 與範例也照這個方式示範：P2-2 會把「兩人互猜」排為 P1，排序理由只寫使用者價值，配對與設定答案寫成實作前提，P2-6 可依 Rule 2 檢查，E1、E2、E6 可滿足。但 P1 互猜故事需要配對進房與答案時要怎麼處理，Rule 2 改正後仍沒有依據，E3、E4 需要 R2 |
| R2 | `s-specify`／故事規則 Rule 1（第 2、3 條與 Good／Bad Example） | 缺失 | 觀察：Rule 1 第 4、5 行要求「只實作該故事時，必須仍能展示並驗證其價值」與「`Independent Test` 必須描述只實作該故事時的驗證方式」，但沒有說明故事需要其他故事先提供的能力或資料時怎麼處理；Good／Bad Example（第 7～29 行）也沒有這種情況。1A2B 產出 US3 的 `Independent Test` 寫「以兩位玩家進入猜測階段」（第 90 行），直接以狀態作為準備。推論：在現行規則下，AI 只能靠依賴排序讓前置能力先出現；R1 改正後，核心故事排到前面，若沒有判斷標準，AI 可能把核心體驗必要的能力（例如兩人進到同一房間）寫成 `Given` 帶過，也可能把要驗收的成果寫進 `Given` | 假設 Rule 1 說明：少了前置能力核心體驗就不成立時，把最小版本併入該故事；只是資料或狀態前提時寫在 `Given`；且 `Given` 不得預先完成要驗收的成果：配合 R1 改正，P2-2 會讓 P1 互猜故事涵蓋最小的配對進房，題目或答案等狀態寫在 `Given`，E3、E4 可滿足；E5、E7 照常適用 |
