## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `.agents/skills/clarify-over-specs/rules/spec-寫回-格式規範.md` Rule 2；由 `SKILL.md` Phase 2 步驟 4、6 套用 | 不可檢查 | 觀察：Rule 2 第 1 點只處理「被決策推翻的舊敘述」；第 2 點寫「不得留下與決策矛盾的 FR、NFR……」，但沒有說明什麼算矛盾，也沒有說明要拿哪些敘述和決策比對。Good／Bad Example 只示範同一個值（24 小時改 2 小時）出現在多處。觀察：P2-4 寫完只用 grep 檢查 FR-002 的同一個值；P2-6 判定「驗證通過」。推論：執行者把 Rule 2 理解成「同一個值或同一句話要一起改」。FR-009 和 FR-019 沒有共用的值，它們的矛盾只在「預約先提交、管理員才按確認」這個先後情境下出現，所以 P2-6 無法依 Rule 2 判定違反（依據上兩項觀察）。觀察：同一模型在 `analyze` 以「同一情境的行為說法不同」（`analyze/rules/分析問題-格式規範.md` Rule 1 F 類）比對時，從同一份 spec 找出 F1 | 假設 Rule 2 規定：寫回後，找出和決策涉及同一個操作、狀態或實體的既有敘述，逐條檢查「兩個操作同時或先後發生」時是否要求不同結果。P2-4 會找到 FR-009、US1 情境 12、Edge Cases、SC-002、Assumptions；FR-009 等可由 FR-019 推出一致寫法（設定成功時沒有未結束預約，被拒絕時都不變），P2-4 改寫，E1 成立。SC-002 的量測時點不能只從決策推出，見 R2 |
| R2 | `.agents/skills/clarify-over-specs/rules/spec-寫回-格式規範.md` Rule 2；`SKILL.md` Phase 2 步驟 7 | 缺失 | 觀察：Rule 2 第 2 點無條件要求「不得留下矛盾」；Rule 1 第 3 點要求「不得加入使用者沒有決定的行為」。兩條規則都沒有說明「消除矛盾需要使用者新的決定」時要怎麼做。P2-7 只把「答案引出的新缺口」與「違反憲法、需要使用者決定的內容」排入佇列，沒有指名「寫回造成、需要使用者決定的矛盾」。推論：R1 改正後，遇到 SC-002 這種要決定量測時點的矛盾，執行者沒有規則可依，可能自行決定時點來滿足 Rule 2，違反 Rule 1 與 E2（依據上述觀察；本次因 R1 沒有發現矛盾，這個情況沒有實際發生） | 假設 Rule 2 規定「無法只從決策推出一致寫法時，不自行決定，排入提問佇列；題數用完時在回報列為 Outstanding 或 Deferred」，P2-7 把它排在佇列前面：第 1 輪寫回後 P2-7 排入「SC-002 在同時發生時怎麼計算」，第 2 輪還有 2 題可問，使用者可決定；題數用完時 P3-2 回報兩處位置。E2 成立；E3～E6 的步驟不受影響 |
