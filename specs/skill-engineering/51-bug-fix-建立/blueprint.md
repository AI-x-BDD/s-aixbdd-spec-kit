````markdown
# SOP

## Phase 1 -- 確認評估報告

1. `READ` 使用者指定的代號或路徑，列出 `specs/bugs/` 底下各代號目錄與其中的 `assessment.md`、`fix.md`，並執行 `git status --short`，建立「候選清單」與「變更基準」。
2. `THINK` 決定「修正目錄」：使用者有指定時用 `specs/bugs/<代號>/`；沒有指定時，用「候選清單」中唯一一個有 `assessment.md`、沒有 `fix.md` 的目錄；把「修正目錄」中的 `assessment.md` 記為「評估報告」，`fix.md` 記為「修正報告路徑」。
3. `CHECK` 「評估報告」不存在時，請使用者先執行 `bug-assess` 並停止；使用者沒有指定且有多個目錄符合時，列出這些目錄請使用者指定並停止。
4. `READ` 「評估報告」全文，建立「修正契約」：核准狀態、核准段（核准的修法、不在本次修正範圍）、澄清紀錄、修法首選的各項、要改的檔案、要補的測試、轉回 SDD 流程的項目與風險。
5. `CHECK` 核准狀態不是「已核准（…）」或澄清紀錄有「待回答」時，回報原因與下一步（回到 `bug-assess` 完成澄清或核准），不修改任何檔案並停止。
6. `WRITE` 「修正報告路徑」已存在時，詢問使用者是否覆寫。
7. `CHECK` 「修正報告路徑」已存在時檢查使用者回覆：同意覆寫時繼續；拒絕或未回覆時不修改任何檔案並停止。

完成條件：已取得「變更基準」、「修正契約」與尚未被占用或已同意覆寫的「修正報告路徑」，評估報告已核准且沒有待回答的問題。

## Phase 2 -- 套用核准修法

1. `WRITE` 用 3～6 點向使用者列出將執行的核准修法項目與要改的檔案，不等待回覆；從本步驟到 Phase 3 結束，不向使用者提問。
2. `READ` 實作修法時，讀取 `rules/修正範圍-格式規範.md` 的所有 Rule，建立「修正範圍檢查清單」。
3. `WRITE` 依「修正契約」與「修正範圍檢查清單」，實作下一個核准的修法項目，並新增或修改該項目對應的測試。
4. `CHECK` 依「修正範圍檢查清單」判斷本項目和「修正契約」的差異：屬於補充時記入「偏離紀錄」後繼續；屬於判斷錯誤時把新發現記入「偏離紀錄」，停止修改程式並保留已改的內容，進入 Phase 3；還有未實作的核准修法項目時返回步驟 3，全部完成時進入步驟 5。
5. `DELEGATE` 執行「修正契約」中要補的測試列出的測試與命令，取得「驗證結果」；需要對外網路或會刪除、覆寫既有資料的命令不執行，記入「驗證結果」。
6. `CHECK` 「驗證結果」有本次修改造成的失敗時，依「修正範圍檢查清單」修正後返回步驟 5，最多 3 輪；第 3 輪仍失敗時，記入「偏離紀錄」為判斷錯誤並進入 Phase 3；失敗的測試沒有涉及本次修改的檔案與行為時，視為和本次修改無關，只記入「驗證結果」，不修改。

完成條件：每個核准的修法項目都已實作，「驗證結果」沒有本次修改造成的失敗；或已因判斷錯誤停止，新發現已記入「偏離紀錄」。

## Phase 3 -- 修正報告與回報

1. `READ` `templates/fix.md` 與 `templates/fix.example.md`，建立「修正報告樣板組」。
2. `WRITE` 依「修正報告樣板組」、「修正契約」、「偏離紀錄」與「驗證結果」，把修正報告寫入「修正報告路徑」；狀態：核准修法項目全部完成且沒有判斷錯誤時寫「已套用」，因判斷錯誤停止且已修改程式時寫「部分套用」，因判斷錯誤停止且沒有修改程式時寫「未套用」。
3. `CHECK` 確認修正報告的標題、開頭欄位與表格欄位和「修正報告樣板組」一致，沒有殘留 `{{`；執行 `git status --short` 和「變更基準」比對，確認本 Skill 造成的變更只有「修正範圍檢查清單」允許的檔案與「修正報告路徑」，而且沒有 commit；修正報告未通過時修正後重新檢查；有其他由本 Skill 造成的變更（包含測試產生的暫存檔）時進入步驟 4，沒有時進入步驟 5。
4. `WRITE` 還原步驟 3 找到的其他變更，然後返回步驟 3。
5. `WRITE` 向使用者回報「修正報告路徑」、狀態、修改的檔案、驗證結果、偏離與未執行的項目，並給出下一步：狀態為「已套用」時接 `bug-test`；為「部分套用」或「未套用」時，依偏離重新執行 `bug-assess`。

完成條件：修正報告已寫入「修正報告路徑」並通過步驟 3 的檢查，已向使用者回報下一步。
````

不加腳本：候選目錄、核准狀態、`{{` 殘留與變更範圍檢查，都可以用 `ls`、`grep`、`git status --short` 單一命令完成，依約束分配規則寫在步驟內文。修正的內容與偏離判斷要讀程式，程式無法判斷。

加 1 組樣板：`fix.md` 有固定的段落、欄位與表格，約束的是整份產出檔案的結構。
