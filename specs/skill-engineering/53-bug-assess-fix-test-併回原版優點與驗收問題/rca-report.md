# 根因報告：bug-assess、bug-fix、bug-test－併回原版優點與驗收問題

- 紀錄目錄：`specs/skill-engineering/53-bug-assess-fix-test-併回原版優點與驗收問題/`
- 問題證據：
  - 3 份藍圖第 8 節的執行紀錄：`specs/skill-engineering/50-bug-assess-建立/blueprint.md`、`51-bug-fix-建立/blueprint.md`、`52-bug-test-建立/blueprint.md`。
  - 實際產出：`specs/bugs/pickup-test-time-dependent/`（`assessment.md`、`fix.md`、`test.md`）。
  - 原版比較：本次對話中的比較結果（建議併回第 1～8 項），原版檔案在 `.spec-kit/v1.4.2/extensions/bug/`。
  - Skill 檔案：`.claude/skills/bug-assess/`、`bug-fix/`、`bug-test/` 的 `SKILL.md`、`rules/`、`templates/`。
  - `clarify/rules/盤點高影響需求缺口與提問排序判準.md` Rule 3。

## 1. 使用者回報的問題

使用者要求做兩件事：

1. 併回原版 bug extension 的 8 項優點：破壞性命令經同意後可以執行、沿用對話中的代號、「不成立」的 4 種理由、嚴重度的 4 個面向、風險的 5 個面向、`bug-fix` 依改到的路徑執行檢查、`bug-test` 自己決定回歸範圍、搜尋線索清單。
2. 修正 3 份藍圖第 8 節記錄的 Skill 問題。這些問題是 S1～S4 驗收時發現的。執行者每次都自行補做，或照字面執行後得到不準確的結果。
