````markdown
## Phase 2 -- 逐一執行任務

1. `READ` 讀取 `rules/任務實作-格式規範.md` 的所有 Rule，建立「實作檢查清單」。
2. `READ` 依「實作檢查清單」，讀取「任務狀態」的 `context`（tasks.md 的 Tests 政策、Reference Loading Contract、Path Conventions、Dependencies & Execution Order 與 Notes），建立「執行脈絡」，並建立空的「受阻任務」與「決策紀錄」。
3. `DELEGATE` 在本 Skill 目錄執行 `uv run --script scripts/tasks_state.py next <tasks.md 絕對路徑> [--scope <執行範圍>] [--skip <受阻任務 ID>...]`，取得「目前任務」；若缺少 `uv`，依 https://docs.astral.sh/uv/getting-started/installation/ 的目前平台安裝說明安裝後重試，安裝失敗時回報原因並停止。
4. `CHECK` 腳本退出狀態不為零時，依標準錯誤輸出修正參數後重新執行步驟 3；「目前任務」的 `task` 為 `null` 時進入 Phase 3。
5. `READ` 依「執行脈絡」的 Reference Loading Contract 與「實作檢查清單」，讀取「目前任務」列出的所有 Must Read 部位，建立「任務參考」。
6. `READ` 尚未載入時，讀取 `rules/自主決策-格式規範.md` 的所有 Rule，建立「決策檢查清單」。
7. `READ` 尚未載入時，讀取 `rules/專案衛生-格式規範.md` 的所有 Rule，建立「專案衛生檢查清單」。
8. `WRITE` 依「目前任務」、「任務參考」、「實作檢查清單」、「專案衛生檢查清單」與「決策檢查清單」實作任務；遇到 Optional 的 Why 所描述的情況時，讀取該 Optional 部位。
9. `READ` 尚未載入時，讀取 `rules/任務驗證-格式規範.md` 的所有 Rule，建立「驗證檢查清單」。
10. `CHECK` 依「驗證檢查清單」驗證本任務，取得「驗證結果」；未通過時修正後重新驗證，最多 3 輪；第 3 輪仍未通過時依「決策檢查清單」處理，任務記入「受阻任務」時略過步驟 11。
11. `DELEGATE` 在本 Skill 目錄執行 `uv run --script scripts/tasks_state.py check <tasks.md 絕對路徑> <任務 ID>`，把本任務標為 `[X]`；若缺少 `uv`，依 https://docs.astral.sh/uv/getting-started/installation/ 的目前平台安裝說明安裝後重試，安裝失敗時回報原因並停止；退出狀態不為零時，依標準錯誤輸出回到步驟 3 取得腳本指定的目前任務，不得以其他方式修改 tasks.md 的核取方塊。
12. `WRITE` 回報本任務進度，第一行固定為「<任務 ID> 已通過，回寫後繼續下一個任務」（受阻時為「<任務 ID> 受阻，繼續下一個任務」），之後寫出讀取的 Must Read 與 Optional 部位（Optional 附觸發情況）、驗證命令與結果、本任務的決策；決策同時依「決策檢查清單」加入「決策紀錄」。
13. `CHECK` 「目前任務」的 `closes_phase` 為 `true` 時，依「驗證檢查清單」執行該 Phase 的 Checkpoint 驗證，未通過時修正後重新驗證，最多 3 輪，仍未通過時依「決策檢查清單」記入「決策紀錄」；之後返回步驟 3。

完成條件：範圍內每個任務都已標為 `[X]` 或記入「受阻任務」，每個完成的 Phase 都已執行 Checkpoint 驗證。
````
