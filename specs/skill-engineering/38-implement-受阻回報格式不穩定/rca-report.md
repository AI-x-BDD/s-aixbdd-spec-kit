# 根因報告：implement－受阻回報格式不穩定

- 紀錄目錄：`specs/skill-engineering/38-implement-受阻回報格式不穩定/`
- 問題證據：本紀錄目錄的 `問題證據.md`；測試 session 對話紀錄 `7900ae6a-a459-484a-8ea3-7bf72af77f37.jsonl`；`.agents/skills/implement/SKILL.md`、`rules/自主決策-格式規範.md`、`scripts/tasks_state.py`；紀錄 28、29、37

## 1. 使用者回報的問題

紀錄 37 修改後以 `user-verify-skill` 重跑，受阻行為正確，但回報格式不符合：

1. 受阻任務沒有逐一輸出「<ID> 受阻，繼續下一個任務」與原因。
2. 完成報告的「憲法遵循」沒有列出「憲法偏離」「未套用規則」「因憲法衝突而受阻的任務」。
3. 憲法衝突受阻的決策紀錄理由沒有寫出憲法檔路徑與 Rule 編號。

使用者判定不通過，並選擇以腳本處理受阻的方向（方案 A）。

## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `implement`／`SKILL.md` Phase 2 步驟 11、13 的受阻分支、步驟 4 與 12 的 `--skip`、Phase 3 步驟 2 的受阻與「憲法遵循」；`rules/自主決策-格式規範.md` Rule 3 的受阻理由 | 載體過弱 | 觀察：步驟 13 以文字要求「受阻時改為輸出『<任務 ID> 受阻，繼續下一個任務』與受阻原因」；打勾路徑則由 `check` 輸出 `progress`。觀察：受阻任務清單只存在於 AI 記憶與每次手寫的 `--skip`，`status` 不提供受阻清單，Phase 3 步驟 2 的子項全靠 AI 重組。觀察：第 219 則的 `--skip` 含已完成的 T005；紀錄 37 S1 子代理有正確輸出，真實 session 沒有，結果不穩定。推論：受阻進度行、受阻原因欄位與受阻清單都有明確輸入輸出，可由腳本產生並檢查，目前只以文字交給 AI，與紀錄 29 R4（打勾後續跑提醒只靠文字）同類 | 假設受阻改由腳本處理：腳本只接受目前發出的任務、依原因強制要求憲法檔與 Rule、依賴 ID 或根因，輸出固定進度行，並保存受阻清單供 `next` 略過與 `status` 輸出。P2-13 直接原文輸出腳本結果（E1）；決策紀錄理由取自腳本欄位（E3）；P3-2 依 `status` 的受阻清單填寫「受阻任務」與「因憲法衝突而受阻的任務」（E2）；`--skip` 不再由 AI 累加；清除時機由腳本規定（E5）；其餘流程不變（E4） |
